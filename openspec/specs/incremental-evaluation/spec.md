# incremental-evaluation Specification

## Purpose
提供增量评估能力，通过检测数据集变化并复用历史结果，避免对未变化题目的重复评估，显著降低评估时间和成本。

## Requirements

### Requirement: 数据集指纹计算

系统 MUST 计算每道题的 SHA256 内容指纹，并生成题目 ID 到指纹的映射。指纹 MUST 覆盖题目 ID、标题、描述、难度、约束、标签、unsupported_reason、输入输出模式、入口、分阶段测试、判题配置及判题契约版本。仅供审计的来源和导入信息不影响规范化后的执行内容时，指纹 MUST 保持一致。

#### Scenario: 计算单个题目指纹

- **WHEN** 系统加载一道题
- **THEN** 系统对其规范化后的评估相关字段计算指纹

#### Scenario: 计算数据集指纹映射

- **WHEN** 系统加载完整题目集
- **THEN** 系统生成题目 ID 到内容指纹的映射

#### Scenario: 题目内容变化导致指纹变化

- **WHEN** 编写提示、选择策略、执行测试或判题所用的题目字段变化
- **THEN** 该题目的指纹 MUST 变化

#### Scenario: 判题契约升级

- **WHEN** 当前判题契约与历史指纹所用的契约不同
- **THEN** 系统 MUST 重新评估受影响题目，并保留原历史报告

#### Scenario: 审计字段变化

- **WHEN** 只更新来源 URL、导入备注等纯审计信息，且规范化后的执行内容相同
- **THEN** 题目指纹保持不变

### Requirement: 历史运行记录持久化

启用增量评估时，系统 MUST 在保存完整运行结果后，保存运行元数据、版本化执行配置指纹、数据集指纹和结果路径。

#### Scenario: 保存运行记录

- **WHEN** 启用增量评估的运行完整保存结果
- **THEN** 系统在 `results/.incremental/history.json` 中保存该运行记录，重复保存相同 run ID 时只保留一条记录

#### Scenario: 记录包含完整元数据

- **WHEN** 系统保存运行记录
- **THEN** 记录 MUST 包含 run_id、timestamp、strategy、model、dataset_fingerprint、result_path、执行配置指纹及其版本

#### Scenario: 历史索引文件不存在时自动创建

- **WHEN** 首次启用增量模式且历史文件不存在
- **THEN** 系统自动创建历史索引并记录完整结果

### Requirement: 增量检测

系统 MUST 从采用当前指纹版本且有效执行配置兼容的历史中选择候选，再比较题目指纹。执行配置 MUST 覆盖 provider、模型、有效端点、生成参数、全部策略及其参数、策略路由、沙箱和影响执行语义的版本。

#### Scenario: 完全匹配历史运行

- **WHEN** 当前数据集指纹和执行配置完全匹配某次历史运行
- **THEN** 系统识别出题目无变化，CLI 按现有完整评估路径执行

#### Scenario: 部分题目变化

- **WHEN** 兼容历史中有 2 道题指纹不同、8 道题未变化
- **THEN** 系统识别出 2 道变化题和 8 道未变化题

#### Scenario: 检测新增题目

- **WHEN** 当前数据集中存在候选历史没有的题目 ID
- **THEN** 系统将其标记为新增题目

#### Scenario: 检测删除题目

- **WHEN** 候选历史包含当前数据集中已不存在的题目 ID
- **THEN** 系统将其标记为删除，当前报告不计入该结果

#### Scenario: 策略配置不一致时拒绝增量

- **WHEN** 任一策略的参数、策略集合或策略顺序变化，即使首个策略名称相同
- **THEN** 系统 MUST 拒绝复用该历史

#### Scenario: 模型不一致时拒绝增量

- **WHEN** 当前使用的模型与某次历史运行不同
- **THEN** 系统 MUST 拒绝复用该历史运行

#### Scenario: 有效生成配置不一致时拒绝增量

- **WHEN** 模型、provider、有效端点或温度、系统提示等参数变化，且没有其他兼容历史
- **THEN** 系统 MUST 完整评估当前选集

#### Scenario: 旧历史缺少当前版本指纹

- **WHEN** 历史记录缺少执行指纹、缺少版本或版本未知，且没有其他兼容历史
- **THEN** 系统 MUST 完整评估当前选集并保留原历史

### Requirement: 历史结果复用

系统 MUST 在增量模式下，仅评估变化的题目，并从历史结果中加载未变化题目的评估结果。

#### Scenario: 复用未变化题目的结果

- **WHEN** 增量检测识别出 8 个未变化题目
- **THEN** 系统从历史结果文件中加载这 8 个题目的 ExecutionResult

#### Scenario: 仅评估变化题目

- **WHEN** 增量检测识别出 2 个变化题目
- **THEN** 系统仅对这 2 个题目执行评估策略

#### Scenario: 历史结果文件缺失时回退

- **WHEN** 历史索引指向的结果文件不存在
- **THEN** 系统记录警告并回退到全量评估

#### Scenario: 历史结果文件损坏时回退

- **WHEN** 历史结果文件无法解析为有效 JSON
- **THEN** 系统记录错误并回退到全量评估

### Requirement: 结果合并

系统 MUST 将复用的历史结果与新评估结果合并，生成完整的策略报告。

#### Scenario: 合并生成完整报告

- **WHEN** 8 个题目复用历史结果，2 个题目新评估完成
- **THEN** 最终报告包含全部 10 个题目的结果

#### Scenario: 保持结果可追溯性

- **WHEN** 合并结果
- **THEN** 每个 ExecutionResult 的来源（新评估或历史复用）MUST 可追溯

#### Scenario: 统计信息准确性

- **WHEN** 生成策略报告的汇总统计
- **THEN** 成功率、平均耗时等指标 MUST 基于完整的合并结果计算

### Requirement: CLI 集成

系统 MUST 提供 `--incremental` 命令行选项，启用增量评估模式。

#### Scenario: 启用增量模式

- **WHEN** 用户运行 `python -m src.main --config config.json --incremental`
- **THEN** 系统启用增量检测和结果复用

#### Scenario: 默认禁用增量模式

- **WHEN** 用户未指定 `--incremental` 标志
- **THEN** 系统执行传统的全量评估

#### Scenario: 显示增量检测结果

- **WHEN** 增量模式启用且检测到可复用的历史
- **THEN** 系统在评估开始前输出：未变化题目数、新增题目数、修改题目数

#### Scenario: 提示无可用历史

- **WHEN** 增量模式启用但无匹配的历史运行
- **THEN** 系统提示用户将进行全量评估并保存历史

### Requirement: 错误处理

系统 MUST 在增量模式下优雅处理各种异常情况，并在必要时回退到全量评估。

#### Scenario: 增量索引损坏时回退

- **WHEN** `history.json` 文件存在但格式无效
- **THEN** 系统记录错误、忽略损坏的历史、执行全量评估

#### Scenario: 并发写入冲突时重试

- **WHEN** 多个进程同时尝试更新历史索引
- **THEN** 系统使用文件锁机制避免数据损坏

#### Scenario: 指纹计算失败时拒绝增量

- **WHEN** 无法为当前数据集计算指纹（如题目格式异常）
- **THEN** 系统记录错误并拒绝增量模式，要求全量评估

### Requirement: 数据集变化检测

系统 SHALL 按题目粒度持久化内容指纹与结果位置，再次运行时按版本化的执行配置指纹选取兼容历史，识别新增、修改、未变和删除的题目。

#### Scenario: 识别变化题目

- **WHEN** 配置兼容，数据集有一道题修改约束、一题新增、其余未变
- **THEN** 系统分别标记修改题和新增题，仅允许复用其余未变题

#### Scenario: 无匹配历史运行

- **WHEN** 不存在兼容的历史运行记录
- **THEN** 系统执行全量评估并给出明确提示

### Requirement: 增量选集与结果复用

只有每个当前结果分组对每道未变题都有且只有一条可读取的历史结果，系统才 SHALL 宣布增量复用并将执行题集缩小到新增题与修改题。系统 SHALL 从按组保存的历史结果 JSON 中加载未变题并标记 `source="reused"`。常规评估按策略分组，按难度选择策略的评估使用汇总分组。历史文件缺失、损坏或覆盖不完整时 SHALL 回退全量评估。

#### Scenario: 只评估变化题目

- **WHEN** 增量模式下数据集含 3 道未变题、1 道修改题、1 道新增题，且当前分组均可完整复用
- **THEN** 本次评估只执行 2 道变化题，3 道未变题的结果从历史复用

#### Scenario: 历史结果损坏回退

- **WHEN** 历史结果文件损坏无法解析
- **THEN** 回退全量评估并输出明确日志，不产生错误退出

#### Scenario: 历史结果缺项或重复时回退

- **WHEN** 新增策略、缺少某当前策略的结果文件，或可解析的文件中有未变题缺项或重复
- **THEN** 系统在输出增量复用提示前回退全量评估，报告与新历史指向的结果文件均对每个当前策略覆盖全部当前题目且每题仅一条记录

### Requirement: 合并报告真实重算

合并后的策略报告 SHALL 从合并后的结果列表真实重算：通过数/成功率/平均尝试次数/token/估算成本（按定价口径累计）与难度分布，SHALL NOT 使用硬编码占位值；合并摘要 SHALL 呈现复用与新增的数量。

#### Scenario: 合并报告指标完整

- **WHEN** 增量运行完成并合并历史结果
- **THEN** 报告的 total 为全部题目数、成功率与成本与合并结果一致（非 0 占位）、难度分布覆盖全部难度

### Requirement: 增量运行来源与恢复

系统 MUST 在报告中记录版本化的执行配置指纹和直接复用来源，保留现有结果来源标记。恢复增量运行时 MUST 恢复原题集、兼容性条件和复用来源，完整统计每个分组中的每道题一次。

#### Scenario: 追溯复用来源

- **WHEN** CLI 保存合并后的增量报告
- **THEN** 能从报告定位复用结果的历史运行及其脱敏配置，并识别当前运行的执行配置指纹

#### Scenario: 恢复中断的增量运行

- **WHEN** 用户使用匹配的配置与数据集恢复中断的增量运行
- **THEN** 系统继续未完成的派发任务，合并同一历史来源，完整统计当前选集且每题每分组仅出现一次

#### Scenario: 恢复所需来源不可用

- **WHEN** 恢复增量运行时原复用来源或已保存的复用选择无法通过校验
- **THEN** 系统明确报告恢复失败，不产生缺项的增量报告

### Requirement: 运行级动态条件

当共享预算或动态历史示例会影响单题执行，且无法验证历史运行与当前执行条件等价时，系统 MUST 完整评估当前选集。

#### Scenario: 共享预算影响派发

- **WHEN** CLI 增量运行启用了运行级预算限制或按难度预算限制
- **THEN** 系统按当前预算评估完整选集

#### Scenario: 策略读取动态示例

- **WHEN** 当前策略使用运行历史中的动态示例池
- **THEN** 系统评估完整选集，使每道题基于当前可用示例执行
