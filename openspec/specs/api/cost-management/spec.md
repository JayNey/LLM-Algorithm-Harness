# api/cost-management Specification

## Purpose
提供按用户隔离的任务费用查询、时间段汇总、趋势和分项统计，统一 evaluation、benchmark、实验与 A/B 的已知费用及完整性语义，并支持预算配置、执行累计、预警规则和定价覆盖版本追溯。

## Requirements

### Requirement: 成本查询聚合

系统 SHALL 从既有业务表（evaluations/experiments/benchmark_runs/ab_tests）按 owner 作用域聚合成本：按 id 解析单任务成本、按时间段输出用户汇总、按日趋势序列与按来源类型/模型/策略的分解；时间段参数非法时 SHALL 返回 400。实验及 A/B 的实际调用费用 SHALL 按 UTC 发生时间持久化；运行中、暂停、取消和失败任务已发生费用 SHALL 保留，同一事件重放、完成单元恢复及重复消息 SHALL 不重复计费。缓存命中 SHALL 仅产生已知零增量。

#### Scenario: 跨表任务解析

- **WHEN** 以 benchmark run 的 id 请求任务成本
- **THEN** 返回该 run 的 cost_usd 与状态；以不存在的 id 请求返回 404

#### Scenario: 空时间段返回空序列

- **WHEN** 查询无任何花费记录的时间段
- **THEN** 汇总为 0、趋势与分解为空数组而非错误

汇总、趋势、分项、任务报告和预算 SHALL 使用同一 owner 范围内的已知费用；task_count SHALL 按来源和任务去重，已有 evaluation 与 benchmark SHALL 不因新记录而双计。响应 SHALL 保留现有字段及容器，兼容增加已知金额、完整性、未知记录数量和原因；缺价格、缺用量及历史缺口 SHALL 明确未知，完全未知单任务金额 SHALL 为 null，部分已知返回已知小计并标记不完整。

#### Scenario: 持久化至 HTTP 且状态独立
- **WHEN** 实验及 A/B 已发生可定价调用后暂停、取消或失败
- **THEN** HTTP 单任务、汇总、趋势、分项和报告可核对已知费用，其他用户不可见

#### Scenario: 日期与重复执行
- **WHEN** 查询调用发生日期或在完成检查点上恢复，重复投递相同消息或回放相同费用事件
- **THEN** 日期过滤含该日全部 UTC 记录，同一消耗不重复计入；实际新调用作为新消耗记录

#### Scenario: 未知与历史回填
- **WHEN** 响应缺价格或缺用量，或迁移前任务只有总 tokens
- **THEN** 不估算未知金额，已知小计与不完整状态同时返回；历史回填只采用明确保存的金额快照，重复执行回填不重复计费

### Requirement: 用户预算配置与使用情况

系统 SHALL 为每用户维护一份预算配置（全局上限、按难度分配、阈值行为 pause/downgrade），upsert 语义；使用情况 SHALL 返回全局 used/remaining/percentage 与按难度的比例估计（basis 字段注明估计口径）。

#### Scenario: 未配置预算的用量查询

- **WHEN** 用户未配置预算即查询使用情况
- **THEN** 返回 used 统计且 cap 为 null，而非错误

全局预算展示与执行读取 SHALL 采用与费用统计相同的已知累计来源，包含实验及 A/B 在所有任务状态下的已保存费用；执行读取 SHALL 不把未知金额当作已知免费。新增费用有明确难度时 SHALL 按实际加入，原有 evaluation 的展示比例估计 SHALL 保持注明 basis。

#### Scenario: 四来源预算一致
- **WHEN** 同一用户有 evaluation、benchmark、实验和 A/B 费用
- **THEN** 全局预算展示和执行读取的已知累计与不限定日期的费用汇总相等，并保持用户隔离

### Requirement: 预警规则与触发历史

系统 SHALL 支持预警规则的创建/更新/删除/列表（threshold_pct、channel、target），非法通道与越界阈值 SHALL 被拒绝；响应中的 webhook/邮件目标 SHALL 脱敏；触发历史 SHALL 从 alert_events 按 owner 返回。

#### Scenario: 非法规则被拒绝

- **WHEN** 提交 threshold_pct 为 0 或 channel 为未知值的规则
- **THEN** 返回 400 且不落库

#### Scenario: 目标脱敏

- **WHEN** 列出包含 webhook URL 的规则
- **THEN** 响应仅含脱敏后的目标（保留协议与主机）

系统 SHALL 在 Web 评估开始及单元成本提交后按 owner 检查启用规则，以个人全局预算和已知累计成本触发 Slack、HTTPS Webhook、SMTP 或 log。每个规则、阈值和上限组合 SHALL 在现有历史保留最近一次已完成的投递结果（`succeeded` 或 `failed`）；同一规则、阈值与上限的成功通知 SHALL 在后续单元及任务恢复时去重。失败 SHALL 有界重试且脱敏，不阻断评估或预算动作；下一次 worker 恢复允许重试。

站内预算预警 SHALL 在已知累计成本达到启用规则阈值时生成，并且不得等待外部渠道发送成功。保存或更新规则 SHALL NOT 生成站内通知。外部渠道的成功、失败和重试 SHALL 只写入既有 alert_events 历史，不得用该历史代替站内预警，也不得因为发送失败而删除已经生成的站内预警。

#### Scenario: Web 规则真实发送

- **WHEN** 用户保存启用的 Slack、Webhook 或邮件规则且累计已知成本达到阈值（含 100%）
- **THEN** worker 向规则目标发送预算摘要并记录该用户成功历史

#### Scenario: 恢复去重与失败隔离

- **WHEN** 成功规则再次达到相同上限阈值或 worker 恢复，另一个渠道发送失败
- **THEN** 成功规则不重复发送，失败不影响其他规则、评估结果或预算暂停，恢复时可重试失败规则并更新同一历史记录

#### Scenario: 未启用和其他用户规则

- **WHEN** 规则禁用、属于其他用户、无个人全局预算或尚未达到阈值
- **THEN** 不发送该规则且不产生成功历史

#### Scenario: 站内预警不依赖发送结果

- **WHEN** 已知累计成本达到启用规则阈值，但外部渠道发送失败或仍在重试
- **THEN** 当前用户有一条对应的站内预算预警，外部失败仍只反映在投递历史上

#### Scenario: 投递历史保留失败和旧成功记录

- **WHEN** 一次投递耗尽重试，或读取升级前已保存的成功记录
- **THEN** 当前账号历史分别返回 `failed` 和 `succeeded`，保留实际渠道，且不包含渠道地址和原始错误

#### Scenario: 保存规则不产生站内预警

- **WHEN** 用户保存或更新启用规则，但已知累计成本尚未达到阈值
- **THEN** 不生成站内预算预警，也不写入成功投递历史

### Requirement: 定价目录与覆盖版本

系统 SHALL 合并 PricingManager 内置定价、自定义文件与数据库覆盖行（覆盖优先）返回定价目录。登录用户 SHALL 能读取目录和历史，管理员 SHALL 能追加覆盖。普通用户追加覆盖 SHALL 返回 403。自定义覆盖 SHALL 以追加版本方式入库（同 model 多行，最新生效）并支持追溯历史。既有保存和历史接口 SHALL 接受含斜杠的完整模型 ID，URL 编码只解码一次，目录键、保存响应及历史归属 SHALL 保持模型原值；普通模型地址和 200 字符长度上限 SHALL 保持兼容。输入及输出单价 SHALL 各自接受有限的非负数，`0` 表示已知免费。

#### Scenario: 覆盖生效且可追溯

- **WHEN** 对同一 model 先后提交两次自定义定价
- **THEN** 目录查询返回最新版本，同时可查询到两条历史版本记录

#### Scenario: 含斜杠模型的真实 HTTP 往返

- **WHEN** 管理员经真实 HTTP 向 Qwen/Qwen2.5-7B-Instruct 的编码地址追加两次定价并查询历史
- **THEN** 保存响应与目录键保留完整模型名，历史按最新优先返回该模型的两个版本

#### Scenario: 编码与历史路径不混淆

- **WHEN** 分别保存普通模型、含多层斜杠、末尾 history、字面 %2F 或 URL 特殊字符的模型并查询各自历史
- **THEN** 各模型原值独立保存，历史只属于所请求模型，百分号不会重复解码

#### Scenario: 扩展路径保留认证与校验

- **WHEN** 对含斜杠模型未认证访问或提交过长模型名、空模型名或非法价格
- **THEN** 请求被拒绝且不新增定价记录

#### Scenario: 零价覆盖和已知费用

- **WHEN** 管理员保存零价覆盖，随后查询目录、历史或使用该定价和已知 token 用量计费
- **THEN** 目录和历史保留零价，该单价对应的费用为已知零成本，缺失定价的费用继续标记为未知

#### Scenario: 普通用户只读共享定价

- **WHEN** 普通用户读取定价目录或历史并尝试追加定价
- **THEN** 读取成功，追加返回 403，历史保持原样

### Requirement: 个人预算执行控制

系统 SHALL 在每个 Web 评估单元派发前按所有者读取个人预算及已知累计成本，达到全局上限或该单元难度上限时执行 pause/downgrade。全局用量 SHALL 覆盖用户评估累计成本、已完成基准运行成本以及实验和 A/B 所有状态下已持久化的已知调用成本；分难度执行用量 SHALL 采用已持久化评估结果的实际已知成本，不将展示用比例估计视作精确结算。缺少可归属难度的结果仅参与全局用量。控制 SHALL 在单元边界生效，不中断在途调用、不预留跨任务并发额度。

#### Scenario: 全局触顶后暂停
- **WHEN** 已保存 pause，用户已知累计支出达到全局上限
- **THEN** 评估在下一单元前持久化 paused，未开始单元不执行，已完成结果和成本保留

#### Scenario: 分难度触顶
- **WHEN** 某难度实际已知成本达到其上限，其他难度未触顶
- **THEN** 只有执行该难度单元时触发动作，其他难度继续使用原策略

#### Scenario: 降级实际执行并可追溯
- **WHEN** 已保存 downgrade，某单元适用的个人上限已达到
- **THEN** 该单元实际采用 vanilla，持久化结果记录 executed_strategy 和 cost_downgraded，保留原单元身份避免结果冲突

#### Scenario: 单任务上限及手动暂停优先
- **WHEN** 个人配置 downgrade，但单任务上限已达到或用户请求暂停
- **THEN** 任务暂停而不派发下一单元

#### Scenario: 恢复重新检查
- **WHEN** 预算暂停后用户调整预算并恢复评估
- **THEN** 按最新预算重新判断，仅执行未完成单元，不重复累计成本；预算仍不足则继续暂停

#### Scenario: 用户隔离与未配置兼容
- **WHEN** 当前用户未保存预算，或只有其他用户的支出与预算
- **THEN** 评估沿用原策略和单任务约束，不受其他用户影响

### Requirement: 个人成本优化使用结果与完整费用

个人成本优化报告 SHALL 仅使用当前用户已完成的评估和基准运行。评估组合的准确率 SHALL 为持久化成功单元数除以计划的题目与策略组合数，范围为 [0,1]。无结果证据时准确率 SHALL 为未知。费用缺失、定价不完整或存在历史证据缺口的组合 SHALL 排除出已知成本排名与建议。

#### Scenario: 多策略与执行失败

- **WHEN** 一题执行两种策略且两个结果均失败，或仅有一种成功
- **THEN** 传入建议的通过数分别为 0 或 1，分母均为 2，准确率分别为 0 或 0.5

#### Scenario: 历史结果只覆盖部分计划

- **WHEN** 已完成评估缺少部分结果，或仅保留进度记录
- **THEN** 部分结果使用完整计划分母且费用未知，完全没有结果的准确率也为未知

#### Scenario: 基准费用小计和零费用

- **WHEN** 一个基准组合的任一运行缺少完整性证据，另一个组合有明确完整的零费用
- **THEN** 前者显示未知费用，后者显示零费用，两者均不参与性价比排名

### Requirement: Web 评估美元预算遇到未知费用时暂停

设置任务自身美元上限的 Web 评估 SHALL 在模型缺价时暂停首个单元派发；执行中出现未知费用时 SHALL 阻止同一单元的后续模型请求和重试，并暂停剩余单元派发。已记录单元的已知费用及未知标记 SHALL 在重新投递和恢复时保留，重放同一单元 MUST NOT 重复累计。

#### Scenario: 恢复后保留预算判断

- **WHEN** 有任务美元上限的 Web 评估在记录未知费用后暂停并恢复
- **THEN** 未知记录仍阻止后续派发，已知小计和未知单元数保持原值

### Requirement: Web HTTP 告警目标由部署者授权

Web Slack 与 Webhook 规则的目标 SHALL 只允许部署者配置的完整 HTTPS URL。系统 SHALL 精确匹配完整目标，不使用通配符、域名后缀或 URL 前缀授权。默认空白名单 SHALL 拒绝 Web HTTP 告警。创建和更新规则 SHALL 对最终状态执行相同策略，不合法时返回 400 且不持久化任何本次字段修改。错误和响应 SHALL 不泄露目标凭据或白名单内容。SMTP、log 和部署者本地 CLI 目标 SHALL 保持既有配置行为。

#### Scenario: 拒绝未授权网络目标

- **WHEN** 普通用户创建 Slack/Webhook 规则，目标是白名单之外的回环 IPv4、IPv6、私网、链路本地地址，或解析至私网的域名
- **THEN** 返回 400，不创建规则、不发出 DNS 查询或 HTTP 请求，错误不包含目标秘密

#### Scenario: 精确允许公共目标

- **WHEN** 部署者配置可信公共 HTTPS 完整目标，普通用户使用相同完整 URL 创建规则
- **THEN** 创建成功，响应继续脱敏；相同主机上的其他路径、端口、query、伪装后缀或 URL 前缀不因该配置获准

#### Scenario: 默认拒绝和危险 URL 语法

- **WHEN** 白名单为空或无效，或目标含非 HTTPS、内嵌凭据、片段或有歧义的 authority/控制字符
- **THEN** 创建和更新均被拒绝，不枚举配置内容或泄露目标

#### Scenario: 更新最终状态与事务回滚

- **WHEN** 更新目标或通道后最终 HTTP 目标未获准，或只更新启用状态、名称、阈值时原目标已经撤销授权
- **THEN** 返回 400，所有本次变更回滚；合法的 SMTP/log 最终状态仍按原规则处理

### Requirement: Web HTTP 历史规则在投递边界重新授权

Worker SHALL 在投递每条 Web Slack/Webhook 规则前按当前部署配置重新校验完整目标，包括升级前保存的规则。未获授权的目标 SHALL 不进入 HTTP 发送层；失败 SHALL 脱敏记录并保持评估、预算动作及站内预警继续工作。获准 HTTP 投递 SHALL 保留 TLS 证书验证、禁重定向、有界重试与成功去重。白名单目标及 DNS 控制权 SHALL 属于可信部署配置，而非普通用户输入。

#### Scenario: 历史内网规则不能发送

- **WHEN** 数据库已有回环、IPv6、私网或未授权域名规则，且用户已知成本达到阈值
- **THEN** Worker 不向该目标发出请求，历史记录失败且无凭据，其他合法规则和站内通知继续工作

#### Scenario: 授权撤销在投递时生效

- **WHEN** 规则创建后目标从部署配置移除，并以更新后的配置启动 Worker 投递或恢复
- **THEN** 不沿用创建时授权，拒绝发送该规则

#### Scenario: 合法投递与其他通道兼容

- **WHEN** 目标仍精确位于部署白名单，或投递 SMTP/log 规则
- **THEN** 合法 HTTP 目标按既有 TLS 和禁重定向方式发送并保留去重、失败隔离及有界重试；其他通道维持现有行为
