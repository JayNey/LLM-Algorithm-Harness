# frontend/problems-management Specification

## Purpose
为已登录用户提供真实题库元数据浏览、个人题库文件导入与导出及本人评估历史查询，保留可恢复的列表筛选和真实导入进度，并准确呈现校验结果、暂停状态、会话边界和操作限制。

## Requirements

### Requirement: 题库元数据浏览

前端 SHALL 提供题目列表页：服务端分页（limit 1–100）与来源筛选（all/shared/personal，筛选状态可经 URL 恢复），展示 problem_id、标题、难度与来源；来源选项 SHALL 附带题库计数。列表端点只下发元数据，前端 SHALL NOT 展示或伪造题目描述、测试用例或来源链接；SHALL NOT 提供关键词搜索、标签/难度筛选与排序入口（后端无此参数）。

#### Scenario: 来源筛选经 URL 恢复

- **WHEN** 用户以 personal 筛选访问列表并把 URL 分享或在刷新后打开
- **THEN** 列表按 personal 过滤且筛选器状态与 URL 一致

#### Scenario: 元数据之外的字段不出现

- **WHEN** 列表渲染任意题目行
- **THEN** 行内只有 problem_id、标题、难度、来源，无描述/测试用例/来源链接占位

### Requirement: 个人题库导入

前端和服务端的个人题库文件导入 SHALL 仅接受 JSON（`.json`）和 CSV（`.csv`），同步与异步导入使用同一格式范围。前端 SHALL 在导入表单中提示支持格式。前端 SHALL 提供文件导入：小文件走同步直导并展示完整 validation 报告（总数/有效/无效/重复/导入数/库存量与错误明细，错误列表截断时如实提示）；大文件走异步导入（上传 → 触发 → 轮询作业进度至终态）。overwrite 模式 SHALL 要求二次确认并说明整库替换后果。后端拒绝（格式/大小/速率）SHALL 如实展示错误。取消文件选择或在提交前收起面板 MUST NOT 发起上传或导入请求。一次导入请求进行中或异步作业未达终态时，重复操作 MUST NOT 创建额外请求或异步作业。会话变化后，旧会话的迟到响应 MUST NOT 更新新会话的导入状态或以新会话身份重试。前端 SHALL 按当前账号保留活动作业标识，并在刷新或重新进入题库后恢复查询。查询暂时中断时 SHALL 提供针对原作业的重试入口，并维持提交锁直至确认作业终态。前端 SHALL 展示服务端作业状态和成功报告，成功后重新读取题目列表与来源计数。

#### Scenario: YAML 文件被拒绝

- **WHEN** 用户尝试导入 `.yaml` 或 `.yml` 文件
- **THEN** 前端在上传前提示仅支持 JSON/CSV，直接调用同步导入或请求为已上传的 YAML 文件创建异步导入作业时，服务端也拒绝该导入

#### Scenario: 同步导入报告呈现

- **WHEN** 用户导入一个含重复与无效条目的小文件
- **THEN** 报告展示 total/valid/invalid/duplicates/imported 与错误明细列表，截断时提示条数上限

#### Scenario: overwrite 需确认

- **WHEN** 用户选择 overwrite 模式并提交
- **THEN** 先弹出整库替换后果确认，确认后才发起请求

#### Scenario: 取消文件选择不发起请求

- **WHEN** 用户取消文件选择，或选择文件后在提交前收起导入面板
- **THEN** 前端不上传文件且不创建导入任务

#### Scenario: 重复操作只提交一次

- **WHEN** 用户重复或快速点击开始导入，且该次提交仍在处理或异步任务尚未终态
- **THEN** 该次选择最多发起一个直导请求或创建一个异步导入任务

#### Scenario: 会话变化隔离旧导入响应

- **WHEN** 导入请求发出后用户切换登录会话，旧请求随后返回
- **THEN** 旧响应不覆盖新会话的页面状态，且不以新会话身份自动重试

#### Scenario: 查询中断后继续原作业

- **WHEN** 已创建异步导入作业且进度请求连续三次失败，用户在接口恢复后点击重试、硬刷新页面或重新进入题库
- **THEN** 继续查询同一作业标识，仍未达终态时阻止重新上传或创建作业

#### Scenario: 恢复引用按账号隔离

- **WHEN** 当前账号存在可恢复作业且用户切换到另一个账号
- **THEN** 新账号的题库不显示也不查询旧账号的作业

#### Scenario: 恢复查询后呈现服务端结果

- **WHEN** 查询到原作业进入成功、失败或暂停状态
- **THEN** 如实展示该状态，成功时显示原作业的导入报告并刷新题目列表与来源计数

### Requirement: 题库导出与评估历史

前端 SHALL 提供个人题库导出入口（JSON/CSV 下载），使用当前 Cookie 会话，仅下载该账号的数据；SHALL 为题目行提供评估历史视图：读取该题执行历史并在前端聚合评估次数与通过率，仅展示本人数据。切换题目时 SHALL 从首页加载历史，上一题的迟到响应 MUST NOT 更新当前抽屉。

#### Scenario: 导出下载

- **WHEN** 用户点击导出并选择格式
- **THEN** 浏览器发起带凭据的下载请求并保存有效文件

#### Scenario: 访问 Cookie 到期时下载

- **WHEN** 用户选择导出 JSON 或 CSV，访问 Cookie 已过期
- **THEN** 浏览器通过共享会话机制刷新后下载当前账号的文件；若会话已无法刷新，应用引导重新登录

#### Scenario: 历史聚合

- **WHEN** 用户打开某题的评估历史
- **THEN** 展示该题历次执行记录与聚合的次数/通过率，无记录时如实提示

#### Scenario: 切换题目时从首页读取

- **WHEN** 用户翻到题目 A 的第二页，再打开题目 B 的评估历史
- **THEN** 题目 B 的首次请求使用 `offset=0`，并显示 B 的首页记录

#### Scenario: 迟到响应按题目隔离

- **WHEN** 题目 A 的历史请求尚未返回，用户打开题目 B 的评估历史
- **THEN** A 的迟到响应不会覆盖 B 的加载状态或记录

#### Scenario: 同题翻页

- **WHEN** 当前题目还有更多历史记录且用户点击下一页
- **THEN** 抽屉查询并展示同一题目的下一页

### Requirement: 暂停导入状态说明

题库导入页在异步导入状态为 paused 时 SHALL 说明当前页面不提供该导入任务的恢复或取消操作；SHALL NOT 引导用户前往不存在的通用任务管理页面。界面 SHALL 提供避免重复提交的安全建议；任务持续暂停时，提示用户联系管理员并提供当前导入任务标识。

#### Scenario: 题库导入暂停

- **WHEN** 题库导入进度为 paused
- **THEN** 页面说明无法在此恢复或取消、避免重复提交，并显示供管理员排查的任务标识

### Requirement: 从 LeetCode 导入公开单题

个人题库导入面板 SHALL 支持已登录用户通过 LeetCode 国际站公开题目链接追加一题。服务端 SHALL 校验域名和题目路径，仅通过现有导入器查询 LeetCode 公共端点，保存题面、难度、标签、规范化来源和可解析的公开样例。该操作 MUST NOT 写入其他账号或共享题库。

#### Scenario: 导入公开题目并查看来源

- **WHEN** 用户提交 Two Sum 等有效公开题目链接
- **THEN** 页面显示等待状态，阻止重复提交，并在成功后刷新列表与来源计数
- **AND** 打开本人题目时可查看题面和可点击的 LeetCode 来源链接

#### Scenario: 同一账号重复导入

- **WHEN** 本人题库已经有该题
- **THEN** 保留已有记录，返回并显示题目已存在；其他账号仍可独立导入

#### Scenario: 无效链接、题目不存在或受限、限流和超时

- **WHEN** 用户提交非支持链接，或公开接口返回题目不存在、受限、限流或超时
- **THEN** 提示相应原因，且不写入题库

#### Scenario: 样例或入口需要人工补全

- **WHEN** 公开题面有效，但无法可靠提取公开样例或 Python 入口
- **THEN** 导入该题并保留既有需人工补全状态，个人题目详情显示该状态

#### Scenario: 个人题目详情按账号隔离

- **WHEN** 用户打开非本人的个人题目 ID
- **THEN** 详情接口不返回该题数据，题库列表继续使用原四字段契约

### Requirement: 批量导入 LeetCode 公开题到个人题库

系统 SHALL 允许已认证用户按标签、难度或两者组合筛选 LeetCode 国际站公开题，并通过后台任务将勾选的题目追加到个人题库。

#### Scenario: 筛选并预览候选题

- **WHEN** 用户按 Medium 和 Dynamic Programming 筛选，并设置单批上限
- **THEN** 系统校验筛选条件和数量上限，显示候选题的题号、标题、难度、标签和来源链接
- **AND** 预览不写入个人题库

#### Scenario: 仅导入勾选项并按用户去重

- **WHEN** 用户确认勾选的题目
- **THEN** 后台任务仅导入该用户选定的公开题，跳过当前个人题库中的重复题
- **AND** 其他用户的个人题库和共享题库不受影响
- **AND** 导入题目保留单题转换产生的需人工补全状态

#### Scenario: 部分失败并按题重试

- **WHEN** 批次中的部分题目遇到限流、超时或访问受限
- **THEN** 已成功导入的题目仍可查看，页面显示处理进度、成功数、重复跳过数、失败数和逐题失败原因
- **AND** 用户可以单独重试可恢复的失败题

#### Scenario: 继续使用已有入口

- **WHEN** 用户提交单题链接或 JSON / CSV 文件
- **THEN** 系统沿用各自的导入流程

### Requirement: 审核个人题库的标签和难度变更

系统 SHALL 允许用户为选中的个人题目预览标签标准化和基于本人历史评估的难度重标注，并保存经过审核的题集版本。

#### Scenario: 核对预览和依据
- **WHEN** 用户选择个人题目、历史评估和通过率阈值后请求预览
- **THEN** 系统逐题显示原标签、标准标签、附带依据的建议标签、原难度、建议难度、有效样本数和通过率
- **AND** 统计排除未执行记录，零有效样本时保留原难度并说明原因
- **AND** 预览不写入源题库

#### Scenario: 只应用批准项
- **WHEN** 用户逐项批准变更并保存
- **THEN** 系统创建保留题目 ID 的个人题集版本，仅应用获批项
- **AND** 用户刷新后可以打开新版本并使用其标签、难度和题目创建评估
- **AND** 源题库与历史评估详情继续可访问

#### Scenario: 处理无变更或过期预览
- **WHEN** 没有批准的可应用变更，或源题库在预览后已更新
- **THEN** 系统提示原因，不保存版本

#### Scenario: 限制版本与历史访问
- **WHEN** 用户在预览、保存、打开版本或创建评估时引用他人的题目、历史评估或题集版本
- **THEN** API 拒绝该请求
