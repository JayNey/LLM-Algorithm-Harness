# frontend/auth-session Specification

## Purpose
让用户在 Web 界面注册、登录并保持会话，在访问失效后刷新或回到登录页，以及主动登出。

## Requirements

### Requirement: 用户注册

注册页 SHALL 收集用户名、邮箱、密码和确认密码。打开注册页时，用户名输入框 SHALL 自动获得焦点。用户名 MUST 为 3–64 个字符，且只含字母、数字、下划线、点或连字符。邮箱 MUST 为 3–254 个字符，且匹配本地部分、`@` 和含点的域名；本地部分与域名 MUST NOT 包含空白或额外的 `@`。密码 MUST 为 12–1024 个字符，且与确认密码一致。密码输入 MUST 不明文展示。提交前未满足这些规则时，页面 MUST 指出未通过的项，且 MUST NOT 发送注册请求。注册成功后 SHALL 进入登录页，且 MUST NOT 把用户直接标为已登录。

#### Scenario: 注册成功

- **WHEN** 用户提交符合规则且未被占用的用户名、邮箱和密码
- **THEN** 页面进入登录页，并提示可以登录

#### Scenario: 打开注册页

- **WHEN** 用户打开注册页
- **THEN** 用户名输入框自动获得焦点

#### Scenario: 确认密码不一致

- **WHEN** 用户提交的确认密码与密码不同
- **THEN** 页面指出两次密码不一致，且不发送注册请求

#### Scenario: 用户名或邮箱已被占用

- **WHEN** 注册请求返回用户名或邮箱不可用
- **THEN** 页面保留已填写的非密码内容，并显示该错误

#### Scenario: 邮箱的点不在域名中

- **WHEN** 用户提交形如 `a.b@c` 的邮箱
- **THEN** 页面指出邮箱无效，且不发送注册请求

### Requirement: 用户登录

登录页 SHALL 接受用户名或邮箱，以及密码。打开登录页时，用户名或邮箱输入框 SHALL 自动获得焦点。密码输入 MUST 不明文展示。用户 MUST 能选择记住我。用户名或邮箱为空、超过 254 个字符，或密码为空、超过 1024 个字符时，页面 MUST 指出未通过的项，且 MUST NOT 发送登录请求。凭证错误时页面 SHALL 显示失败提示并留在登录页。登录成功后 SHALL 显示欢迎提示；若本次访问带有本站内的原地址，SHALL 回到该地址；否则 SHALL 进入仪表盘。原地址 MUST 是本站相对路径，MUST NOT 接受外部网址。有用户名时欢迎文案 MUST 包含该用户名；没有用户名时文案 MUST 为「欢迎回来」。

#### Scenario: 使用邮箱登录并记住我

- **WHEN** 用户用邮箱和正确密码登录，并选择记住我
- **THEN** 会话在浏览器重新打开后仍然存在

#### Scenario: 打开登录页

- **WHEN** 用户打开登录页
- **THEN** 用户名或邮箱输入框自动获得焦点

#### Scenario: 登录成功

- **WHEN** 用户用正确密码登录且当前用户名可用
- **THEN** 页面显示包含该用户名的欢迎提示，并进入原地址或仪表盘

#### Scenario: 不记住我

- **WHEN** 用户用正确密码登录且未选择记住我，随后本次浏览会话结束
- **THEN** 再次打开应用时会话不存在

#### Scenario: 密码错误

- **WHEN** 用户提交错误密码
- **THEN** 页面显示登录失败，并保持未登录

#### Scenario: 回到登录前的页面

- **WHEN** 未登录用户先打开题目路径，再在登录页用正确密码登录
- **THEN** 应用显示题目页

#### Scenario: 拒绝外部回跳

- **WHEN** 登录前记录的地址指向其他网站
- **THEN** 登录成功后进入仪表盘

#### Scenario: 用户名或邮箱为空

- **WHEN** 用户不填写用户名或邮箱就提交登录
- **THEN** 页面指出请输入用户名或邮箱，且不发送登录请求

#### Scenario: 密码为空

- **WHEN** 用户不填写密码就提交登录
- **THEN** 页面指出请输入密码，且不发送登录请求

#### Scenario: 输入超过长度上限

- **WHEN** 用户提交超过 254 个字符的用户名或邮箱，或超过 1024 个字符的密码
- **THEN** 页面指出对应的长度错误，且不发送登录请求

### Requirement: 受保护请求携带访问令牌

已登录状态下发往本应用 API 的请求 SHALL 带上 `Authorization: Bearer` 和当前 access token。注册、登录和刷新请求 MUST NOT 依赖已有 access token。access token 缺失、过期或被拒绝时，若本地仍有 refresh token，客户端 SHALL 只发起一次刷新并在成功后重试原来的请求一次。同一时刻多个请求需要刷新时 SHALL 共用这一次刷新。刷新失败或没有 refresh token 时，客户端 SHALL 清除本地会话并进入登录页。

#### Scenario: 请求自动带上访问令牌

- **WHEN** 已登录用户触发一个受保护 API 请求
- **THEN** 该请求包含当前 access token 的 Bearer 认证头

#### Scenario: 访问令牌过期后刷新

- **WHEN** 受保护请求因 access token 无效被拒绝，且本地 refresh token 仍有效
- **THEN** 客户端获得新的 token 对，并成功重试原来的请求一次

#### Scenario: 刷新失败

- **WHEN** 刷新请求被拒绝
- **THEN** 本地会话被清除，用户进入登录页

### Requirement: 登出

已登录用户 SHALL 能从导航发起登出。登出时客户端 SHALL 用当前 access token 请求撤销当前登录会话，清除本地 access token、refresh token 和用户身份，然后进入登录页。撤销请求失败时，本地会话仍 MUST 被清除。

#### Scenario: 登出成功

- **WHEN** 已登录用户选择登出且撤销请求成功
- **THEN** 本地会话消失，页面进入登录页，后续受保护页面不再直接打开

#### Scenario: 撤销请求失败仍退出

- **WHEN** 已登录用户选择登出且撤销请求失败
- **THEN** 本地会话仍然消失，页面进入登录页

### Requirement: 当前用户身份

登录成功后，应用 SHALL 读取当前用户的用户名并在导航中显示。未登录时导航 MUST NOT 显示用户身份。读取当前用户被拒绝且刷新无法恢复会话时，SHALL 按受保护请求的失败规则进入登录页。

#### Scenario: 导航显示用户名

- **WHEN** 用户登录成功且当前用户资料可读
- **THEN** 导航显示该用户的用户名

### Requirement: 认证页面可在窄屏完成

登录页和注册页 SHALL 在移动宽度下完整展示字段、提交按钮，以及登录与注册之间的切换入口。用户 MUST 能用回车提交当前表单。请求进行中时，提交控件 SHALL 显示加载状态并避免重复提交。

#### Scenario: 窄屏切换到注册

- **WHEN** 视口为移动宽度且用户在登录页选择注册
- **THEN** 注册表单的用户名、邮箱、密码、确认密码和提交按钮可见

#### Scenario: 回车提交

- **WHEN** 用户在已填写且通过校验的登录表单中按下回车
- **THEN** 客户端发送登录请求
