# frontend/result-reports Specification

## Purpose
让已登录用户通过现有认证会话，从评估结果详情安全下载当前运行的 Markdown、HTML 或 CSV 即时报告，正确处理权限、文件响应和失败，并准确区分完整评估与仅含部分已记录结果的报告。

## Requirements

### Requirement: 结果详情下载即时报告

已登录用户在结果详情页 SHALL 能选择 Markdown、HTML 或 CSV 格式并下载当前运行的即时报告。请求 MUST 使用该结果的 `run_id`、应用配置的 API 地址和现有认证会话；MUST NOT 用 `evaluation_id` 替代缺失的 `run_id`。下载 SHALL 使用响应提供的文件名或安全的格式默认名，并明确展示请求、权限或服务错误。无可用 `run_id` 时，下载操作 SHALL 不可用且 MUST NOT 发送请求。

#### Scenario: 下载三种报告格式

- **WHEN** 用户打开带有效 `run_id` 的结果详情并选择 Markdown、HTML 或 CSV
- **THEN** 应用向当前配置的报告接口请求该 `run_id` 对应的格式，并下载可打开的文件

#### Scenario: 运行标识缺失

- **WHEN** 结果详情没有有效 `run_id`
- **THEN** 报告操作不可用或说明暂不可下载，且不会改用 `evaluation_id` 发起请求

#### Scenario: 会话刷新与权限错误

- **WHEN** 报告请求需要刷新会话、用户无权访问运行或服务返回错误
- **THEN** 应用沿用现有会话刷新流程；成功时下载文件，失败时显示明确错误且不生成伪文件

#### Scenario: 重复点击和下载资源

- **WHEN** 同一格式的报告正在请求，或浏览器已触发文件下载
- **THEN** 重复请求受到抑制，临时下载资源最终得到释放

### Requirement: 报告完整性提示

结果详情 SHALL 根据当前结果可用性说明报告范围。运行中、暂停、失败、取消、未知或结果不完整时，界面 MUST 明确说明下载可能仅包含已记录的部分结果，MUST NOT 将其描述为完整评估；已确认完整的结果不得显示部分报告警告。

#### Scenario: 部分或非完整结果下载

- **WHEN** 当前结果为运行中部分结果、暂停、失败、取消、未知或不完整
- **THEN** 报告下载附近显示准确的部分结果说明，不声称结果完整

#### Scenario: 完整结果下载

- **WHEN** 当前运行的结果被确认为完整
- **THEN** 可下载报告且不会显示部分结果警告
