## Context
首页当前重导出 BusinessPage。既有评估列表按 created_at、id 正序分页且 owner-scoped，total 是全量过滤结果；系统状态仅管理员可读。

## Decisions
- 独立首页替换 Mock，沿用工作台样式和主题；现有其他示例页面保持原行为。
- 评估总数及最近任务先查询第一页 limit=5，超过五条时按 total-5 查询末五条并反转；运行中和已完成分别使用 limit=1 的过滤查询 total。不用最近五条推算全量指标。
- 费用读取 /costs/summary 的 total_cost_usd，文案明确当前用户全部记录的已记录费用，包含评估、实验、基准和 A/B。移除没有汇总契约支撑的 Pass@1 和基线结论。
- 复用 useRole，仅 ready/admin 请求系统状态；角色加载、失败和普通用户分别显示诚实反馈。复用严格解析的 monitoring client 和状态文案。
- 各资源独立结算，失败不抹去其他成功区域；错误重试和手动刷新重新 GET。会话 marker、客户端、请求轮次绑定快照，cleanup abort，迟到响应不写入。

## Risks / Trade-offs
- 分页不是原子快照：并发增删可能改变末页；标注最近一次读取时间，手动刷新重新读取。
- 后端列表内部读取全量是既有实现；首页请求数有界，不新增后端汇总接口。
- 不自动轮询，避免首页频繁触发系统探测；提供明确刷新入口。
