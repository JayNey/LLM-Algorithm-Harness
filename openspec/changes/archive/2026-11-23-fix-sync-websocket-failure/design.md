# WebSocket 同步失败处理设计

## Context

见 proposal.md。现有 isCurrent 依赖 conn 身份与 closed 标志，但 conn 在 connectSocket 返回后才赋值。最小脚本确认同步 onError 只有 connecting、1 次 HTTP 请求、0 个定时器；直接抛错还会逃逸 start。异步失败已具备轮询和退避逻辑，应继续复用。

## Decisions

- 在工厂调用前登记当前连接身份；初始化期间暂存回调，在句柄赋值后按原顺序处理。这样同步错误被守卫接受，同步 open 也不会访问空句柄。
- 捕获连接工厂构造异常，直接复用同一失败处理路径；若初始化已报告失败后又抛错，只记录一次失败。
- 错误时先使连接失效并解除当前绑定，再关闭已返回的句柄，避免 close 同步回调重复处理。初始化失败后不把已失效连接重新绑定为当前连接。
- 保持异步事件、HTTP 快照、退避次数、权限与会话处理语义；通过假时钟验证真实状态迁移与请求行为。
- 不仅在 React 适配器异步延迟 onError：那只能修复单个适配器，无法处理直接抛错与观察器自身的初始化契约。

## Risks / Trade-offs

- 回调可能在关闭句柄时重入：先标记 closed 并解除绑定，再清理资源，旧回调受身份守卫阻止。
- 初始化回调顺序可能包含 open 后 error：按顺序重放，错误清除订阅定时器；已失效连接事件不产生新订阅或状态更新。
- 构造期间抛错时没有可清理的返回句柄：仅清理观察器身份，继续轮询和退避。

## Validation

先增加同步 onError 与构造抛错的失败回归，确认真实 RED，再实现最小修复；覆盖异步失败、3/6/12/30 秒退避与失败上限、恢复 live、旧事件隔离、dispose 和初始化期间 open。执行前端测试命令及可用的构建、ESLint 检查；记录环境限制与实际结果。
