# WebSocket 连接生命周期认证

## Context

动机与范围见 proposal.md。`api/routes/ws.py` 仅在建连时调用 `AuthService.authenticate`，后续订阅与事件转发使用缓存的 principal。认证服务本身已核验 JWT 到期、会话撤销和用户存在性；密码变更按现有 api/password-change 规范保留会话（用户已确认沿用）。进度流通过独立转发任务向同一连接发送事件，清理集中在路由的 finally。

## Goals / Non-Goals

实现 `specs/api/progress-streaming/spec.md` 的连接生命周期鉴权要求，覆盖查询参数和访问 Cookie 两种入口。实现限于现有 WebSocket 路由与测试，复用认证和流接口。

## Decisions

- 固定保存建连时选中的实际 token，每次重新认证使用同一凭据，防止连接借用后续 HTTP Cookie 变化延续权限。
- 在接收客户端动作后、快照发送前和每次事件转发前重新认证，覆盖撤销后新订阅、重复订阅和持续推送。特别核对订阅建立等 await 边界后的有效性。
- 每秒重新检查连接认证，确保空闲连接也关闭。可采用接收循环超时或受管理的监控任务，保持一个接收者；事件发送和关闭操作需避免并发竞争及重复关闭。
- 统一处理认证失效与连接终止，返回 4401；既有资源归属失败保持 4403。finally 负责取消并等待所有转发或监控任务，释放全部订阅，包括订阅建立后、完成注册前发生的失败。
- 不使用进程内注销通知代替认证服务检查：直接检查共享认证存储可覆盖其他 API 进程完成的撤销，且无需增加发布协议。

## Risks / Trade-offs

- 重新认证增加数据库读取与 JWT 验证开销。每秒定期检查加敏感操作前检查，以简单局部修复覆盖失效边界；本次不增加缓存，以免恢复撤销窗口。
- 连接同时接收、发送和关闭可能发生竞争。需要统一终止路径，确保不在关闭后继续发送，且断连及失败均进入资源清理。
- 认证服务检查与网络发送之间仍存在不可消除的极短时间窗口；验收针对撤销完成后开始的动作和转发，空闲失效采用一个检查周期的检测边界。
- 时间相关测试应使用可控时钟、同步点或有限超时，避免真实长时间等待与无限阻塞。

## Validation

补充能够复现 issue 的失败回归，随后实现并核对通过；覆盖注销后新订阅及重复订阅、已有订阅事件泄漏、密码变更保留会话、访问令牌到期、Cookie 入口、空闲连接关闭以及订阅释放。执行现有 WebSocket 与认证相关回归、修改文件的 Ruff/Black 检查和 OpenSpec 严格验证。预设为 direct/direct/off：当前会话实施和检查，无独立审查要求。
