## Context

开发模式下 React StrictMode 会先清理再重跑 effect。预算表单的单次读取标记使重跑跳过 GET。空草稿仍可提交，客户端把空的难度项序列化为 `{}`，PATCH 将其视为整个难度对象的替换。

## Decisions

- 复用预算页现有可取消、可重试的资源读取。成功后挂载预算编辑器。
- 比较草稿与最近一次服务端快照，只提交有变更的顶层字段。难度有修改时按既有替换协议提交草稿中的完整难度分配，保留其中未修改的项。显式清空某档时移除该档。
- 请求进行时锁定表单。成功后用响应替换草稿和比较基线，并刷新用量；失败时保留草稿以便重试。

## Verification

用浏览器覆盖正常、延迟、失败重试及 StrictMode 请求取消。核对真实 PATCH 请求、重新加载后的表单及独立 API 回读。补验旧记录、空配置与真实 worker 执行路径。
