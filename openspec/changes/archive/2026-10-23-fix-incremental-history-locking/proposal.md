# 增量历史文件锁修复

## 问题与根因
`save()` 以 w 打开文件，在获取排他锁前截断文件；`load()` 不加锁，可能将短暂的空文件或半写入 JSON 当成损坏历史。写入缓冲区还可能在释放锁后才由 close 刷盘。

## 复现证据
2026-10-23 使用 python3 临时目录运行真实 save/load，在替换的加锁入口中读取历史：原有一条记录变为 bytes=0、loaded_runs=0，并记录 JSONDecodeError。

## 修复目标
在获取锁前保留原文件，锁内完成覆盖、截断和刷盘；读取使用同一排他锁，避免观察写入中间状态。保留文件格式、缺失/损坏文件回退、保存重试与跨平台锁实现。

## 范围
仅修改历史实现与对应测试。恢复既有并发保护承诺，无 public API 或 spec 验收变更。
