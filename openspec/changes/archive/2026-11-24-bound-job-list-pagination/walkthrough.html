数据库分页和独立计数

原来

读取当前用户全部历史实体后，用 Python 切片取当前页。

现在

COUNT 返回匹配总数，LIMIT/OFFSET 只读取当前页；状态与归属筛选和 created_at/id 升序排序保持一致。

原因 请求 20 条时，200 或 400 条历史均只加载 20 个业务实体。

列表配置在数据库内裁剪

原来

完整 JSON 题库快照先传到应用，再删除 problems 和 owner_id。

现在

SQLite json_remove / PostgreSQL JSONB #- 在 SELECT 中裁剪，ORM 仅接收公开配置及快照摘要；库内完整快照保留。

原因 避免列表传输和反序列化完整题目，并保持旧配置、null 与未知公开字段。
