## Context

见 proposal.md。用户确认基于 PR #286 创建新分支；已合并 origin/main，工作基线为 `48ea717b5526cc8198f1b395e4285e58263f8564`，包含 #229 / PR #282 与 #230 / PR #291。

## Goals / Non-Goals

补齐 issue #231 的全部适用质量检查与公开证据。不改变评估行为、全局覆盖率门槛或 mypy Python 3.10 目标；不把 #232 的真实服务联调列为已验证。

## Decisions

- 使用现有 Python 3.11 运行原始 API mypy 命令，不覆盖 `--python-version`。这比接受原报告的替代证据更直接；环境或代码失败必须按原退出码记录并定位。
- 定向 pytest 使用 `--no-cov`；全量 pytest 单独生成 coverage，再顺序执行 src≥90、api≥81 门禁，避免定向覆盖率污染全库结论。
- 用一个 JSON 命令清单和一份文本日志记录工作目录、命令、代码 SHA、起止时间、退出码及输出。前端/静态检查可独立运行；全量测试与 coverage 读取保持顺序。
- 对照 #216–#230 的公开 issue/PR 与实际测试，填入检查矩阵和验收条目。新 CI 链接只能来自真实运行，不能复用旧提交冒充。

## Risks / Trade-offs

- 外部服务、Docker、平台能力缺失可能导致 skip → 保留逐项原因与验证层级。
- 全库门禁发现既有问题 → 先调查；仅修复与真实评估相关的问题，范围外阻塞如实记录，不自行豁免。
- 本 change 主要为验证和文档，无 spec 级行为变化，因此跳过 delta spec。
