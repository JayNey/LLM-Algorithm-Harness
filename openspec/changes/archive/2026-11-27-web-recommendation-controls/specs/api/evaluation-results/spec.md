## ADDED Requirements

### Requirement: 配置 Web 推荐阈值和数量

推荐页面 SHALL 提供失败率阈值和推荐数量输入，默认分别为 0.5 和 20。推荐 API SHALL 接受 failure_threshold（0 < 值 ≤ 1）及 limit（1–100 的整数），省略时使用默认值，非法输入返回明确校验错误。实际推荐 SHALL 应用所选阈值及数量上限，并沿用已有历史权限、候选来源、最少样本和排序规则。页面 SHALL 明示最多选择、保存和带入评估 100 道题；修改参数 SHALL 清除旧预览及选题，避免保存过期结果。

#### Scenario: 阈值改变薄弱组
- **WHEN** 固定历史中某分组失败率为 0.5，用户分别使用 0.5 与 0.75 预览
- **THEN** 该分组只在阈值为 0.5 时被判为薄弱组，候选匹配遵循各次的薄弱组

#### Scenario: 请求超过默认数量
- **WHEN** 可匹配的未评估候选至少有 100 个，用户分别请求 20、30 和 100 道题
- **THEN** 返回数量分别为 20、30 和 100，且顺序遵循现有排名规则

#### Scenario: 参数缺省与非法输入
- **WHEN** 请求省略新增参数，或提交阈值为 0、大于 1，数量为 0、101 或非整数
- **THEN** 省略参数时按阈值 0.5、数量 20 推荐；非法参数得到明确错误，页面空值或越界值不得发起推荐请求

#### Scenario: 保留空状态和访问边界
- **WHEN** 用户切换候选来源、提高最少样本数导致历史不足，或请求不可访问的历史
- **THEN** 结果分别使用相应来源、显示既有空状态或权限错误，不以更大的 limit 绕过现有边界

#### Scenario: 调整参数后保存并继续
- **WHEN** 用户修改参数重新预览，人工选择推荐题目，保存题集并继续创建评估
- **THEN** 请求携带当前参数，页面展示真实返回结果，保存和创建仅使用本次选中题目 ID，且容量提示为 100 道
