# 设计：推荐参数贯通

## Context

动机见 proposal.md，行为契约见 specs/api/evaluation-results/spec.md。现有路由已传 failure_threshold，共享分析已有 limit=20；页面与客户端尚无两个参数的完整输入链路。

## Decisions

- 在现有请求模型添加 limit=20（1–100 整数），路由显式传给 analyze_recommendations，沿用现有阈值校验；不增加接口或改变共享算法。
- RecommendationPanel 增加受控数值输入，和现有参数一样在编辑时清除旧结果与选题。空值、非整数数量或越界值禁用提交并展示边界提示；首轮自动预览使用默认参数。客户端参数类型保持可选以兼容既有调用。
- 推荐上限采用 100，与保存题集、创建评估的现有容量一致。页面给出容量说明；补齐英文翻译。
- 验证采用现有 API 集成测试与前端/mock 浏览器设施。固定历史与足量候选检查阈值的实际效果、20/30/100 返回数、默认行为及非法输入，并覆盖空状态、来源权限和保存继续链路。

## Risks / Trade-offs

100 个候选增加展示规模但仍受现有题集上限约束。默认值由前后端一致设置，使用请求断言和省略参数的后端测试防止漂移。预计影响 7–9 个交付文件（实现、测试及文案），仅涉及已描述范围；如达到 tweak 文件数复核阈值，将按 Runtime 记录继续决定。

## Migration Plan

无需数据迁移；旧客户端省略 limit 时保持 20。回退本次代码即可恢复现有行为。
