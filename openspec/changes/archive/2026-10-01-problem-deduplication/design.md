## Context

当前系统已有题目导入功能（`problem-import/cli-commands`），支持从多个来源导入题目。但缺少去重机制，导致重复题目在数据集中累积。

现有代码结构：
- `src/harness/cli.py` — CLI 入口
- `src/harness/importers/` — 各类导入器实现
- `data/problems.json` — 题目数据集存储格式

题目数据结构包含：`id`、`title`、`description`、`source_platform`、`source_problem_id`、`tags`、`test_cases` 等字段。

## Goals / Non-Goals

**Goals:**
- 提供独立的去重工具，不影响现有导入流程
- 支持两种检测策略：相似度检测（文本分析）和指纹匹配（来源标识）
- 提供交互式和自动化两种操作模式
- 合并时保留更完整的题目信息

**Non-Goals:**
- 不在导入流程中自动执行去重（保持导入流程简洁）
- 不处理题目内容的语义理解（仅基于文本相似度）
- 不支持跨数据集去重（仅处理单个数据集文件）

## Decisions

### 决策 1: 独立命令而非集成到导入流程

**选择：** 实现独立的 `harness problems deduplicate` 命令

**理由：**
- 去重是数据清洗操作，应该是用户主动触发的工具
- 导入流程已有 `--update-strategy` 处理重复，集成去重会增加复杂度
- 独立命令可以在任何时候对现有数据集执行去重

**备选方案：**
- 在导入流程中自动去重 — 但会影响导入性能，且用户可能需要先预览重复情况

### 决策 2: 使用 scikit-learn 进行相似度计算

**选择：** 使用 `TfidfVectorizer` + `cosine_similarity`

**理由：**
- scikit-learn 是成熟的机器学习库，TF-IDF 是标准的文本相似度方法
- 无需训练模型，直接使用算法
- 性能足够处理中等规模数据集（几千到几万题目）

**备选方案：**
- 使用编辑距离（Levenshtein） — 但对长文本计算开销大
- 使用 embedding 模型（如 sentence-transformers） — 但引入额外依赖且对题目文本可能过于复杂

### 决策 3: 双策略检测机制

**选择：** 同时使用指纹匹配和相似度检测

**理由：**
- 指纹匹配（`source_platform + source_problem_id`）可快速识别完全相同的题目
- 相似度检测可发现来源不同但内容相同的题目（如不同平台的同一题目）
- 两种策略互补，提高检测覆盖率

**实现细节：**
1. 先执行指纹匹配（O(n)，快速）
2. 再对无指纹或指纹不同的题目执行相似度检测（O(n²)，较慢）
3. 合并两种策略的检测结果

### 决策 4: 合并策略采用字段完整度优先

**选择：** 保留字段更完整的题目，合并列表字段

**理由：**
- 不同来源的同一题目，可能有些字段更完整（如测试用例、标签）
- 简单保留第一个或最后一个可能丢失信息

**合并规则：**
- 比较非空字段数量，保留更完整的题目作为主版本
- 对于列表字段（`tags`、`test_cases`），合并去重
- 在主版本中添加 `merged_from` 字段记录被合并题目的 ID

## Risks / Trade-offs

**[风险] 相似度阈值设置不当导致误判**
→ **缓解措施：**
- 默认阈值 0.9 较为保守，可通过 `--threshold` 调整
- 交互式模式让用户确认每对重复题目
- `--dry-run` 模式支持预览检测结果

**[风险] 大规模数据集性能问题**
→ **缓解措施：**
- 指纹匹配优先，减少需要相似度计算的题目对
- 可考虑后续优化：分批处理、使用近似最近邻算法（如 Annoy、FAISS）

**[权衡] 合并策略可能丢失部分信息**
→ **缓解措施：**
- 记录 `merged_from` 字段，保留合并历史
- 建议用户在去重前备份数据集

**[风险] 缺少来源信息的题目无法指纹匹配**
→ **缓解措施：**
- 仅依赖相似度检测
- 在去重报告中统计缺失来源信息的题目数量

## Migration Plan

**部署步骤：**
1. 添加 `scikit-learn` 依赖到 `pyproject.toml`
2. 实现核心去重逻辑 `src/harness/utils/deduplication.py`
3. 在 `src/harness/cli.py` 中添加命令入口
4. 运行单元测试验证功能
5. 在示例数据集上执行 `--dry-run` 测试

**回滚策略：**
- 去重是独立工具，不影响现有功能
- 用户数据在 `--dry-run` 和交互式确认下安全
- 如有问题，用户可从备份恢复数据集
