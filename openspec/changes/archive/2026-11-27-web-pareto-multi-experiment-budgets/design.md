# 简要设计

## Context

动机见 proposal.md。现有 ParetoTab 通过 useResource 自动请求；该 hook 使用 AbortController 和 load 身份隔离结果。createExperimentClient.pareto 已刻意读取未解析 comparison，以保留后端队列兼容校验依赖的快照。后端 src/pareto.py 支持非负预算、多实验兼容性校验，并对预算排序去重。

## Goals / Non-Goals

- 在已有页面和客户端边界完成输入到真实分析的闭环。
- 复用现有认证客户端、分页协议及分析服务；无持久化迁移、额外依赖或模型调用。
- 后端算法、权限、公共 API 与报告导出保持现有范围。

## Decisions

1. 客户端 pareto 接受单 ID 或 ID 数组，兼容已有单实验调用；先按 ID 去重，再读取完整原始报告。所有读取与 POST 共享取消信号；任一失败不发起分析。相较客户端合并数据，这能保留后端权威校验。
2. 页面保留默认当前实验，提供多选及按需加载更多实验。列表按既有 limit/offset/has_more 读取，不自动下载全部历史；选项按 ID 去重，列表失败有重试且不阻断已知当前实验的默认分析。
3. 预算使用一个列表输入，支持逗号、中文逗号及空白分隔。空输入为 []；拒绝非法 token、负数和非有限值。保留数值精度和重复项；服务端决定推荐排序和去重。
4. 输入、加载提示和错误与结果区域分开渲染。复用 useResource 的请求隔离；无效输入和空选择不发分析。实验详情改变时重置 Pareto 表单，避免跨详情残留。失败允许按当前输入重试。
5. 浏览器验收沿用现有 Playwright 脚本设施；固定 comparison 通过隔离 FastAPI TestClient 调用真实路由与 build_pareto_analysis，核对表单、请求参数、实际结果和不兼容错误。客户端测试另覆盖重复 ID、原始字段保留、失败短路与 signal 传递。

## Risks / Trade-offs

- 多实验读取可能较慢 → 请求可取消，切换输入立即隐藏旧结果；不提交部分成功集合。
- 用户列表中实验可能尚未完成或选择后失去访问权 → 沿用服务端读取错误，不依赖前端推断权限或兼容性。
- 预算可能重复且服务端排序 → 请求保留原值，结果按服务端响应显示，避免重复 React key。
- 预计 7 个交付文件 → Open 时明确确认仅文件数超限继续 tweak；超出已确认范围重新复核。

## 验证与回退

执行客户端回归、语言资源检查、受影响文件格式与 lint、前端生产构建、浏览器交互及真实分析路由小数据验收；覆盖单/多实验、分页、重复 ID、预算 0/小数/重复/非法值、两个准确率口径、读取拒绝、不兼容、网络恢复和迟到响应。不调用付费模型。回退本次前端实现与规格即可恢复既有入口，无数据迁移。
