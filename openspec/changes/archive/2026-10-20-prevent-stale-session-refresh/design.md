## 修复方案

刷新开始时记录当前 accessToken 与 refreshToken，在成功写回前比较当前凭证。凭证已清除或替换时，拒绝旧刷新结果，并终止等待它的请求。失败分支也只清除仍匹配的旧会话，避免清除后来登录的新会话。

按凭证值比较，而非对象引用：现有 read 从浏览器存储反序列化对象，正常读取也会产生新对象。只修改 HTTP 模块内部逻辑，不新增公共 API。原有刷新合并及请求重试规则保留。

验证使用可控 Promise 确定请求顺序，不依赖定时等待；真实 HTTP 客户端与会话 store 仅在网络 adapter 边界使用假响应。覆盖提前刷新窗口、401 恢复、清除后迟到成功/失败、切换会话后迟到成功/失败，以及普通刷新回归。

## 范围

修复已有登出语义，不扩展到登录资料请求的异步隔离、跨标签同步或后端会话策略。Token 凭证变化由现有服务端签发机制提供，不引入新的持久化格式。
