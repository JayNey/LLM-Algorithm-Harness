## Why

Issue #161 核对中复现：受保护请求触发刷新，用户登出并清空会话后，迟到的刷新成功会重新写入 Token 和身份，导致前端恢复登录态。

根因为共享 HTTP 客户端刷新成功时无条件 write，失败时无条件 clear，均未检查当前凭证是否仍属于发起刷新时的会话。

## What Changes

- 在处理刷新结果前核对发起刷新时的凭证，过时结果不写回、不清除新会话、不继续重试原受保护请求。
- 增加确定性回归，覆盖主动清除/登出、重新登录及迟到成功/失败；保留有效会话的正常刷新与并发合并。

## Capabilities

恢复 `frontend/auth-session` 现有登出和受保护请求约束，不改变其验收语义；无新增能力、接口或规格变更，使用 `skip_specs: true`。

## Impact

仅前端 HTTP 刷新结果处理及相关 HTTP、store 测试；后端接口、Token 存储格式和路由不变。
