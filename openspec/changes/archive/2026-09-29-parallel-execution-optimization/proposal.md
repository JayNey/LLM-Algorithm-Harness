# Proposal: 并行执行优化

## 动机

当前评估系统采用串行执行模式，导致评估速度较慢：
- 10 个题目 × 4 策略 = 40 次串行调用
- 每次 LLM 调用耗时 5-30 秒
- 总耗时可达 10+ 分钟

这种串行执行方式在评估大量题目时效率低下，限制了系统的实际可用性。

## 目标

实现题目级和策略级的并行执行能力，提升评估速度 5-10 倍，同时保持：
- 成本追踪的准确性
- 资源使用的可控性
- 实时进度监控的可见性

## 范围

本次变更包括：

1. **题目级并行**：多个题目可以同时进行评估
2. **策略级并行**：同一题目的不同策略可以并行执行
3. **资源控制**：
   - 可配置的并发数（max_workers）
   - Docker 容器资源限制
   - LLM API 速率限制控制
4. **进度监控**：使用 rich 库实现实时进度条
5. **成本追踪**：线程安全的成本预算累计器

## 非目标

- 不改变现有的评估逻辑和算法
- 不修改沙箱执行环境的核心机制
- 不影响单题目单策略的执行结果

## 影响范围

主要涉及文件：
- `src/harness/harness.py` - 主评估流程
- `src/harness/executor.py` - 执行器逻辑
- 配置文件 - 添加并行相关配置项
