## Why

上游 issue #20 要求建立离线端到端回归与按需在线验证。现状：CLI→题库→策略→执行器→结果文件的全链路只有零散的单元测试，负向场景（缺失数据集、坏配置、空策略）没有系统断言；在线验证机制（PR #37 引入的 `online` 标记）尚未在文档中正式定义，真实调用与替身测试的区分也没有落到使用文档。

## What Changes

- 新增固定响应模型替身的**离线端到端测试**：覆盖 CLI→题库→策略→沙箱执行→结果文件全链路，对成功链路与失败链路的结果文件、summary 指标、`failure_category` 做精确断言。
- 负向回归：缺失数据集、坏配置文件、空策略列表均以明确错误退出，不产生结果文件、不被宽松断言误判为成功；空策略在 harness 层显式报错。
- CI/入口检查：`--help` 入口可用、online 用例在无凭证时跳过状态可见。
- README 新增"测试与验证"章节：离线回归、online 标记用法、真实调用与替身测试的区分、故障排查（沙箱预检失败/代理/定价缺失）。

## Capabilities

### New Capabilities

- `offline-regression`: 定义离线端到端回归的覆盖范围、负向场景与验证记录区分要求。

## Impact

- 影响 `tests/`（新增 e2e 测试文件）、`src/harness.py`（空策略显式报错）、`README.md`。
- 不改变评测执行语义与结果文件格式（空策略报错为新增校验，属行为收紧，见 design）。
