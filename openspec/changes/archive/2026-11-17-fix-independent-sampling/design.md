# 技术设计

## Context

响应缓存键描述模型请求的有效参数。实验预算围绕逻辑调用准入和响应后的用量结算，实际付费计量另外使用缓存命中标志。实验检查点已经保存完成的组合，CLI 求解任务也已保存完成的题目结果。

## Decisions

- 使用生成入口的内部标记控制缓存读取和写入。Self-Consistency 在单次题目执行中为候选提供身份，多次重复的实验为每个组合提供独立的范围。该标记由客户端消化，供应商参数合并规则保持原样。
- 使用既有调用事件身份记录每次新采样，补充候选或组合身份以及缓存命中信息。组合身份随实验元数据和检查点保存，恢复事件引用原组合；已经完成的组合从检查点直接恢复。未完成的工作按原来的检查点粒度重新开始。
- 新采样绕过旧缓存。普通请求继续使用原缓存键。曾启用缓存的受影响任务使用版本标记区分旧检查点。旧历史可以查看，缺少采样证据的重复范围按历史观察值呈现。

## Risks / Trade-offs

- 独立采样会按实际发生的请求计费，沿用现有逻辑调用预算、请求重试和付费计量。使用同一模拟响应覆盖预算、命中和离线调用次数，避免把输出差异当作独立证据。
- 旧检查点的重复候选可能已合并过响应。涉及该路径时，保留现有文件并显式提示新建运行。原本禁用缓存的检查点维持可恢复性。
