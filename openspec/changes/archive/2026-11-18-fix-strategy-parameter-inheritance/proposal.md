# 策略参数继承与 ToT 搜索配置修复

## Why

Issue #492 中的两个缺陷在 main（8a4d0e1c）仍存在：Web 持久化将省略的策略生成参数变为显式默认值，覆盖模型设置；ToT 工厂创建的实例忽略搜索配置，同时将控制字段转发给供应商。它们影响执行结果和结果复用可信度。

## What Changes

- 实验、A/B、基准的策略保存与加载保留字段显式性，省略参数继承模型配置，用户显式填写的默认值继续优先。
- ToT 从策略配置解析并严格验证四个搜索控制字段，从 Harness 工厂入口实际生效，并从供应商生成参数中剔除。
- 核对配置快照、有效参数记录与阶段 3 的复用兼容规则，区分影响执行的参数语义并隔离不兼容旧结果。
- 历史数据库记录保留已存字段为显式值；无法恢复原始意图时说明需重新保存配置，不启发式删除默认值。
- 两个子问题分别回归；交付时尽可能独立记录修改，最终按 Comet 归档协议提交。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `api/experiment-management`：三条 Web 策略持久化路径保留省略与显式值的区别。
- `strategies/tree-of-thoughts`：配置经 Harness 生效、合法性验证、控制字段与供应商参数隔离。
- `llm-response-cache`：与实际执行一致的有效参数记录及配置复用兼容性。

## Impact

范围限于已有策略参数契约的修复，无数据库 schema 或新增 API。预计涉及三个 API service、策略配置/序列化、ToT、参数过滤、任务指纹及相关配置快照位置，以及 API 数据库、Harness 工厂、参数记录和检查点回归测试与兼容说明。交付文件预计超过 tweak 六文件提示阈值，但不增加需求或架构协调；实际超限时按 Runtime 范围复核取得授权。沿用 current 工作区（main），执行配置 direct/direct/off；验证包含规格一致性、真实 SQLite 往返与离线 SDK 模拟，不调用付费模型。
