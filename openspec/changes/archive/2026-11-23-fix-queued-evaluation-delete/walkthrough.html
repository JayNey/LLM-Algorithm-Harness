01

删除与任务活动状态一致

原来

pending 评估即使已入队仍可删除，任务继续占用额度。

现在

pending/running/paused 关联任务使 can_delete=false，删除先拒绝且不清理文件。

原因 保留 worker 可读取的业务记录，防止孤立活动任务；也检查不再由当前链接指向的同所有者旧任务。

02

同一事务保护清理与删除

原来

先检查，再在事务外清理，最后重新打开事务删除，允许启动插入窗口。

现在

共用用户准入事务锁，刷新并保护任务/评估状态，非阻塞取得执行权后清理与删除，提交后释放执行权。

原因 提交先完成则删除拒绝；删除先持锁则提交回滚且不发布；取消仍执行时清理拒绝。

03

缺陷回归与资源一致性

原来

删除测试允许隐式取消，未覆盖活动任务保护和删除/启动竞争。

现在

补充活动状态/归属/过期链接矩阵、双向竞争、执行未停、清理重试及 HTTP 文件/结果/额度回归。

原因 验证拒绝时无清理副作用，停止后删除可以回收资源且不被延迟发布复活。
