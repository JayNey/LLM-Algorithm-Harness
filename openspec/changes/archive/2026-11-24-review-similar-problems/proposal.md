# Web 相似题审核与合并

## Why

个人题库目前仅能在导入时跳过重复项；已有相似题需要借助 CLI 处理。Issue #474 要求在浏览器内审核候选及合并内容，并保存可用于评估的新版本。

## What Changes

- 在题库「批量治理」中增加「查找相似题」，支持文本相似度阈值、来源指纹依据和候选组预览。
- 复用 CLI 的检测、主版本推荐及列表字段合并函数，逐组选择保留题或跳过，展示对应合并前后字段。
- 只将明确批准的合并保存为新的个人题集版本，记录保留 ID 与被合并 ID，保留未选组和其他题目。
- 预览绑定所有者及源库修订，保存时校验过期；同一次确认重试或并发提交只产生一个版本。
- 新版本沿用现有版本查看与创建评估入口；不修改源题库、历史结果或已有集合中的题目引用。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `problem-deduplication`：增加按所有者隔离、可审核、过期校验及幂等的 Web 合并版本保存。
- `frontend/problems-management`：增加批量治理中的相似题审核与合并版本操作。

## Impact

- 后端：复用 `src/problem_utils/utils/deduplication.py`，扩展个人题库治理服务、认证路由和 `FileStore` 版本持久化。
- 前端：扩展治理抽屉、客户端契约与中英文文案，增加独立相似题审核组件。
- 验证：检测与合并规则、组选择、字段完整性、账号隔离、源库过期、幂等并发、旧引用以及新版本创建评估。
- 预估涉及 10–14 个交付文件（实现、测试、用户文档），超过 tweak 六文件提示线；新增路由限定在既有治理边界内，无需跨层架构重构。Open 确认后仍按 Runtime 范围复核决定继续 tweak 或升级 full。
- 沿用当前工作区 `main`；本阶段仅准备需求产物。新增功能不调用外部模型或启动 Eval。
