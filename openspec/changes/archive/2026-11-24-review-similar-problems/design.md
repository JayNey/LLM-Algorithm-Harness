# 相似题审核与版本保存设计

## Context

动机与边界见 proposal.md。既有 `api/files/governance.py` 和治理抽屉已提供审核及版本入口，`FileStore.dataset_snapshot` 返回所有者绑定的修订摘要，`save_dataset_version` 在写事务内再次检查修订。现有保存缺少幂等回执；独立版本载荷已经可用于评估。

## Goals / Non-Goals

- 在既有治理边界内接入扫描和审核保存，完整验收见两份 delta spec。
- 本次不修改共享题库或 CLI 的交互操作，不重构评估执行流程，不引入后台任务系统或外部依赖。

## Decisions

1. **检测与合并复用核心函数。** 调用来源指纹、文本相似度、完整度推荐和 `merge_problems`。采用 CLI 现有的确定性分组顺序：先来源组，再加入不与已收录组重叠的文本对；返回实际匹配边，避免将传递关系误称为直接相似。空库及空词表单独处理。扫描内存和耗时依据个人题库现有限额验证，必要时在共享工具内以分块计算保持同样阈值语义。
2. **完整预览由服务端生成。** 新治理路由接收阈值；返回源库与候选摘要令牌、候选原题及每个可能保留题的合并结果，前端展示字段差异。保存只接收预览输入、令牌、版本名和组/保留题选择，不信任客户端回传的题目内容。相同源库重算必须得到同样候选身份。
3. **快照保存。** 从完整源库复制，只替换批准组的保留题并移除该组其余题，保存完整新版本。保留题正文与非列表字段保持用户选择，标签和测试列表沿用 CLI 合并；通过 `merged_from` 记录被合并 ID。跳过组及其他题保持不变。版本详情扩展必要的合并记录展示，已有列表和创建评估入口继续复用。
4. **修订校验和幂等回执共用事务。** 对规范化确认内容生成所有者隔离的幂等身份，在 FileStore 增加持久回执与唯一约束；同一事务内先查完成回执，再核验源修订、插入版本及回执。首次保存仍重算并校验预览与组选择；已完成确认重试返回原版本，不因后续源库更新再次创建。版本沿用现有保留策略，已清理的结果返回明确不可用状态，不能重复创建。
5. **复用页面会话与版本导航。** 治理抽屉增加独立相似题页签，默认跳过每组，选择后才批准；切换保留题同步更新差异。阈值变化废弃扫描和选择；扫描请求可取消，保存设置同步提交锁并核对当前会话身份。409 提示重新扫描。保存成功跳转现有题集版本页签。

## Risks / Trade-offs

- 相似度表示文本接近而非题目等价 → 显示匹配依据与完整变更，由用户逐组批准；不自动保存。
- 重算和保存间源库被修改 → 在同一保存事务内复核修订，完整拒绝过期候选。
- 预览包含本人题目的完整字段 → 所有新端点使用既有认证依赖，禁止引用其他账号题库及版本。
- 文件数预计超过六个且增加 Web API → 在进入实施前记录范围复核，获得继续 tweak 或升级 full 的明确决定；不以压缩文件数量牺牲契约测试。

## Migration Plan

FileStore 初始化按现有模式增量创建幂等回执表，已有版本和题库载荷不迁移。回滚应用不修改原数据。新增接口与字段保持向后兼容。

## Validation

后端回归覆盖 CLI 规则复用、阈值边界、空词表、分组不重叠、非推荐保留题、跳过组、完整字段和合并历史、伪造选择、账号隔离、源库变化及事务竞争、重复/并发确认、重启后重试、版本重新读取和创建评估。前端覆盖请求契约、逐组交互、参数与会话隔离、错误和保存导航，并运行相关格式、类型检查与构建。保留旧治理、版本容量和历史引用回归。
