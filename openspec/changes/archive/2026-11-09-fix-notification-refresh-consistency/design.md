## Context

服务端按创建时间和通知 ID 倒序进行游标分页。读取任意分类都返回账号全局未读数。当前通知 store 用同一个 generation 处理列表替换和写操作，后启动的读取可以丢弃已经提交的写操作回读。

## Decisions

- 同筛选刷新从第一页按新游标重读已加载范围，必要时读到旧列表尾部所在位置，避免新增通知挤掉仍可用的后续条目。完整对账后一次更新列表、全局未读数和游标。分页游标失效时从头恢复。
- 分类切换清空旧列表并使在途读取失效。账号继续由会话标识隔离。写操作成功后回读当时的当前分类，期间同分类的普通刷新不会抢占。更晚提交的写操作触发新回读。
- 保留通知 ID 作为 React key，后台对账期间保留当前快照。批量操作仍携带服务端时间作为截止点，以保护刷新期间到达的新通知。
