# Web 评估增量运行与历史结果复用

## Why

Web 用户重新评估题集时，目前每个题目与策略组合都会重新执行，无法像 CLI 一样复用兼容历史。Issue [#475](https://github.com/JayNey/LLM-Algorithm-Harness/issues/475) 要求按执行单元复用本人历史，并在一次完整结果中区分历史度量和本次新增成本。

## What Changes

- 创建页新增默认关闭的「复用历史结果」选项；按题目 × 策略预览预计复用数、重跑数及逐单元原因。
- 服务端以当前用户为边界，比较规范化题目指纹与逐策略执行指纹。仅选择已实际执行、完成且兼容信息完整的本人历史单元；新增、变化、不兼容和无有效历史的单元重新执行。
- 增量评估创建提交时固定完整题目版本、有效执行配置和复用结果副本及来源；预览不调用模型，提交重新核对当前输入并返回最终计划。
- 使用原有任务执行、检查点、执行独占与结果发布路径，将复用单元与实际新跑单元合成完整评估。全部可复用时不发起新增模型调用；没有历史时正常全量评估。
- 结果详情展示复用来源、复用与重跑数量和本次新增费用。保留历史 token、耗时、迭代、原始成本等度量；预算、账户费用和本次 `spent_usd` 只计算实际新增调用。
- 暂停恢复、worker 重投递和任务重试沿用同一固定计划，结果写入和费用结算保持幂等。旧记录缺少指纹时保守重跑。

## Capabilities

### New Capabilities

- `frontend/incremental-evaluation`：创建页复用预览与结果页的来源、数量、新增成本展示及会话隔离。

### Modified Capabilities

- `api/evaluation-execution`：允许兼容历史单元跳过模型执行，增加所有者范围内预览、提交时固定复用计划以及恢复与新增费用语义。
- `api/evaluation-results`：结果详情返回复用来源和运行汇总，将原始结果度量与本次费用分别表达。

## Impact

- 后端涉及请求/响应模型、SQLAlchemy 数据模型与 Alembic 迁移、评估创建与查询服务、认证路由、Celery worker、检查点与产物聚合的相关接入。
- 前端涉及创建页、详情页、客户端、状态和类型、双语文案与相关测试；补充公开 API 说明。
- 复用 `src/incremental/fingerprint.py` 的题目指纹与有效配置指纹方法；Web 为每个策略构造等价配置，不能直接使用 CLI 的整次运行历史选择与合并路径。CLI 行为保持原有契约。
- 新增字段默认关闭/为空以兼容现有客户端和历史数据；不新增运行时依赖。
- 预计超过 tweak 的 6 个交付文件，并涉及公共 API、持久化 schema 与跨前后端协调。Open 仅形成可审阅方案；开始实施前须按预设范围复核取得继续 tweak 或升级 full 的明确选择。
