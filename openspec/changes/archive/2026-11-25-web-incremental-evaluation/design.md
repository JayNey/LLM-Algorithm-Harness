# Web 增量评估设计

## Context

目标与范围见 proposal.md，正式行为以 specs/ 的三个 delta 为准。

- `src/incremental/fingerprint.py` 已对题目内容、三类测试和判题契约计算指纹，对有效模型与执行配置计算带版本指纹。CLI 的历史选择以整次运行配置为粒度，不能直接满足 Web 逐策略复用。
- `api/services/evaluation_service.py` 创建业务记录；`src/tasks/evaluation.py` 在 worker 启动时解析题目并为全部单元创建检查点，沿回调幂等写结果和费用。当前题目固定时点晚于 Issue 要求。
- `EvaluationResult.metrics` 保存原始统计和部分题目元数据，旧记录缺少完整兼容信息。现有任务独占、重投递保护和结果产物发布必须继续适用。

## Decisions

1. **共用解析与指纹逻辑。** 提取可被创建服务和 worker 使用的题目及有效配置解析，遵守本人导入覆盖共享题、显式数据集版本的既有规则。逐策略构造与实际 worker 等价的 HarnessConfig 后调用现有指纹函数，加入 Web 执行契约版本。预览仅解析配置，不创建 LLM 客户端、不运行沙箱预检。不同策略可分别匹配，增加其他策略不使原策略结果失效。动态或无法证明兼容的输入采用保守新跑。
2. **业务库保存不可变计划。** 使用新增的私有 JSON 持久字段保存增量开关、完整题目快照、规范化且无密钥的有效配置、各单元指纹、复用来源及结果副本；迁移为已有记录提供关闭/空默认值。复用副本随本次记录生存，避免原运行删除或 checkpoint 文件丢失后需要重新选择来源。完整题目与隐藏测试不通过响应返回。
3. **预览与创建使用同一规划服务。** 增加受认证的只读预览端点，校验凭证与题目可访问性。普通、选题、显式集合版本与异步创建入口均支持默认关闭的增量字段。创建服务在保存业务记录前重新规划并固定输入，返回最终汇总；规划失败不留下可入队的半成品。
4. **历史候选限定本人真实完成单元。** 只接受已完成运行中已实际执行、兼容信息完整的结果。按完成时间及稳定 ID 确定性选择最新兼容单元；排除未执行、取消和缺少信息的旧结果。复用行保留来源，但不把复用副本再次当成新的实际执行证据。新跑结果保存题目、执行指纹和版本，使后续评估可用。候选查询先限制所有者与所选题目/策略，再比较指纹，避免载入无关历史。
5. **沿用现有单元调度与检查点。** 为完整笛卡尔积创建单位，复用结果按固定副本物化为完成单元，剩余单元走现有真实 worker；SQL 结果和任务进度沿同一幂等键写入。只有存在新跑单元时才初始化所需运行时和模型调用路径。恢复使用固定计划的内容指纹，复用来源不重查；保持跨进程执行独占及消息代际校验。
6. **保留原始成本，单列新增费用。** 新跑单元新增费用等于真实调用费用，复用单元新增费用为零，原始 metrics 不改成零。费用累计、预算守卫、账户额度、未知费用计数和产物汇总读取明确的新增口径；历史无新增字段时回退原有新跑语义。结果 API 额外提供复用/新跑计划数量和新增成本，既有分析保留原始结果度量；前端与导出明确标注费用口径。
7. **前端预览绑定草稿与账号。** 复用开关默认关闭；有效输入变化取消/作废旧请求，使用请求纪元阻止乱序返回。网络错误独立展示，提交后使用服务端最终固定数量。详情页按返回标记显示来源与本次费用，补齐中英文文案。

## Risks / Trade-offs

- 指纹输入与真实执行漂移 → 共用规范化配置构造并测试模型、策略、生成超时、测试与判题元数据变化；不只比较模型名称。
- 重复结算或进度放大 → 对复用和新跑统一使用既有结果幂等键，费用按持久化新增费用差量结算，覆盖 SQL 提交与 checkpoint 回放窗口。
- 敏感题目或凭证泄漏 → 私有计划不进入公开 schema、日志或错误详情；只持久化配置摘要与无密钥配置，历史查询强制 owner 条件。
- 计划体积增长 → 每题只保存一份完整快照，单元引用题目快照；历史查询限制候选范围。预览和详情只返回计数、原因与来源标识。
- 旧记录命中率下降 → 不推断缺失指纹，正常全量评估建立以后可用的兼容历史。
- 公共 API、迁移和前后端协调超出通常 tweak 范围 → Open 确认范围后，Build 在实施前走预设范围复核，由用户明确选择继续 tweak 或升级 full；不静默升级或删减验收。

## Migration Plan

1. 增加向后兼容的可空/默认关闭字段，验证已有数据库升级及新库创建。
2. 后端先支持新字段和预览，旧客户端省略字段保持原行为；前端上线后才显式启用。
3. 回滚应用后新增字段可保留；执行中的增量计划须由支持该版本的 worker 处理，不能让旧 worker 忽略固定计划。

## Validation

使用离线受控模型响应验证实际调用次数，覆盖混合三类题 × 多策略、模型/端点/超时/测试/判题变化、旧历史与取消历史、跨用户、零命中、全命中及零预算。用创建后修改题目/删除来源、暂停恢复和重复投递验证计划稳定与幂等。运行相关 pytest、Ruff/类型检查、前端状态测试、构建、Lint 与浏览器界面验收；不请求真实付费模型调用。
