## MODIFIED Requirements

### Requirement: 数据集指纹计算

系统 MUST 计算每道题的 SHA256 内容指纹，并生成题目 ID 到指纹的映射。指纹 MUST 覆盖题目 ID、标题、描述、难度、约束、标签、unsupported_reason、输入输出模式、入口、分阶段测试、判题配置及判题契约版本。仅供审计的来源和导入信息不影响规范化后的执行内容时，指纹 MUST 保持一致。

#### Scenario: 计算单个题目指纹

- **WHEN** 系统加载一道题
- **THEN** 系统对其规范化后的评估相关字段计算指纹

#### Scenario: 计算数据集指纹映射

- **WHEN** 系统加载完整题目集
- **THEN** 系统生成题目 ID 到内容指纹的映射

#### Scenario: 题目内容变化导致指纹变化

- **WHEN** 编写提示、选择策略、执行测试或判题所用的题目字段变化
- **THEN** 该题目的指纹 MUST 变化

#### Scenario: 判题契约升级

- **WHEN** 当前判题契约与历史指纹所用的契约不同
- **THEN** 系统 MUST 重新评估受影响题目，并保留原历史报告

#### Scenario: 审计字段变化

- **WHEN** 只更新来源 URL、导入备注等纯审计信息，且规范化后的执行内容相同
- **THEN** 题目指纹保持不变

### Requirement: 历史运行记录持久化

启用增量评估时，系统 MUST 在保存完整运行结果后，保存运行元数据、版本化执行配置指纹、数据集指纹和结果路径。

#### Scenario: 保存运行记录

- **WHEN** 启用增量评估的运行完整保存结果
- **THEN** 系统在 `results/.incremental/history.json` 中保存该运行记录，重复保存相同 run ID 时只保留一条记录

#### Scenario: 记录包含完整元数据

- **WHEN** 系统保存运行记录
- **THEN** 记录 MUST 包含 run_id、timestamp、strategy、model、dataset_fingerprint、result_path、执行配置指纹及其版本

#### Scenario: 历史索引文件不存在时自动创建

- **WHEN** 首次启用增量模式且历史文件不存在
- **THEN** 系统自动创建历史索引并记录完整结果

### Requirement: 增量检测

系统 MUST 从采用当前指纹版本且有效执行配置兼容的历史中选择候选，再比较题目指纹。执行配置 MUST 覆盖 provider、模型、有效端点、生成参数、全部策略及其参数、策略路由、沙箱和影响执行语义的版本。

#### Scenario: 完全匹配历史运行

- **WHEN** 当前数据集指纹和执行配置完全匹配某次历史运行
- **THEN** 系统识别出题目无变化，CLI 按现有完整评估路径执行

#### Scenario: 部分题目变化

- **WHEN** 兼容历史中有 2 道题指纹不同、8 道题未变化
- **THEN** 系统识别出 2 道变化题和 8 道未变化题

#### Scenario: 检测新增题目

- **WHEN** 当前数据集中存在候选历史没有的题目 ID
- **THEN** 系统将其标记为新增题目

#### Scenario: 检测删除题目

- **WHEN** 候选历史包含当前数据集中已不存在的题目 ID
- **THEN** 系统将其标记为删除，当前报告不计入该结果

#### Scenario: 策略配置不一致时拒绝增量

- **WHEN** 任一策略的参数、策略集合或策略顺序变化，即使首个策略名称相同
- **THEN** 系统 MUST 拒绝复用该历史

#### Scenario: 模型不一致时拒绝增量

- **WHEN** 当前使用的模型与某次历史运行不同
- **THEN** 系统 MUST 拒绝复用该历史运行

#### Scenario: 有效生成配置不一致时拒绝增量

- **WHEN** 模型、provider、有效端点或温度、系统提示等参数变化，且没有其他兼容历史
- **THEN** 系统 MUST 完整评估当前选集

#### Scenario: 旧历史缺少当前版本指纹

- **WHEN** 历史记录缺少执行指纹、缺少版本或版本未知，且没有其他兼容历史
- **THEN** 系统 MUST 完整评估当前选集并保留原历史

### Requirement: 数据集变化检测

系统 SHALL 按题目粒度持久化内容指纹与结果位置，再次运行时按版本化的执行配置指纹选取兼容历史，识别新增、修改、未变和删除的题目。

#### Scenario: 识别变化题目

- **WHEN** 配置兼容，数据集有一道题修改约束、一题新增、其余未变
- **THEN** 系统分别标记修改题和新增题，仅允许复用其余未变题

#### Scenario: 无匹配历史运行

- **WHEN** 不存在兼容的历史运行记录
- **THEN** 系统执行全量评估并给出明确提示

## ADDED Requirements

### Requirement: 增量运行来源与恢复

系统 MUST 在报告中记录版本化的执行配置指纹和直接复用来源，保留现有结果来源标记。恢复增量运行时 MUST 恢复原题集、兼容性条件和复用来源，完整统计每个分组中的每道题一次。

#### Scenario: 追溯复用来源

- **WHEN** CLI 保存合并后的增量报告
- **THEN** 能从报告定位复用结果的历史运行及其脱敏配置，并识别当前运行的执行配置指纹

#### Scenario: 恢复中断的增量运行

- **WHEN** 用户使用匹配的配置与数据集恢复中断的增量运行
- **THEN** 系统继续未完成的派发任务，合并同一历史来源，完整统计当前选集且每题每分组仅出现一次

#### Scenario: 恢复所需来源不可用

- **WHEN** 恢复增量运行时原复用来源或已保存的复用选择无法通过校验
- **THEN** 系统明确报告恢复失败，不产生缺项的增量报告

### Requirement: 运行级动态条件

当共享预算或动态历史示例会影响单题执行，且无法验证历史运行与当前执行条件等价时，系统 MUST 完整评估当前选集。

#### Scenario: 共享预算影响派发

- **WHEN** CLI 增量运行启用了运行级预算限制或按难度预算限制
- **THEN** 系统按当前预算评估完整选集

#### Scenario: 策略读取动态示例

- **WHEN** 当前策略使用运行历史中的动态示例池
- **THEN** 系统评估完整选集，使每道题基于当前可用示例执行
