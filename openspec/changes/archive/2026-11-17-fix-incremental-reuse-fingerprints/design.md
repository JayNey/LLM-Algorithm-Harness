## Context

CLI 先选择历史，再把实际派发题集缩小到变化题。断点服务会校验实际派发配置和数据集，因此恢复增量运行时还需要找回原来的题集与复用来源。

## Decisions

- 对规范化后的有效配置计算带版本的稳定哈希。输入包括模型、provider、有效端点及相关环境覆盖、生成与重试参数、完整有序的策略配置、难度路由、沙箱、分析开关和执行语义版本。日志级别、报告目录等运行展示信息不参与比较。密钥等敏感值不得新增至持久化配置快照。报告沿用脱敏配置，并记录执行指纹及直接复用来源。
- 本次兼容性按完整运行判断。策略集合、顺序或任一策略参数变化时，完整评估当前选集。逐策略独立复用需要把现有统一选集改为按策略派发，并处理路由和共享预算，本次沿用运行粒度。
- 将标题、描述、难度、标签、约束、入口、输入输出模式、三类测试、判题配置、unsupported_reason 和判题契约版本纳入题目指纹。来源、导入与人工补全备注等字段用于审计，经过模型规范化后，其中实际影响执行的值（如迁移生成的测试或判题配置）仍参与哈希。
- 预算或动态示例池能让单题行为依赖其他题目或历史文件。无法从固定配置证明等价时，完整评估当前选集。
- 增量派发前保存与 run ID 绑定的选择和历史来源。恢复时校验原运行的配置、数据集与复用覆盖，使用同一批变化题和同一历史来源。无法恢复该选择时明确失败，避免输出缺题的报告。完成后按现有方式合并和重算报告，并以 run ID 幂等更新索引。

## Risks / Trade-offs

- 旧历史仍可读取。缺失指纹、版本未知或配置变化时，需要先完成全量评估才能为以后运行提供可兼容历史。
- 共享预算及动态示例场景会少复用一些结果，以维持当前运行的评估条件。题目集无内容差异时继续走 CLI 现有的完整评估路径。
