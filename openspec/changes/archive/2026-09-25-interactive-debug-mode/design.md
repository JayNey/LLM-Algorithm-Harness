## Context

当前系统支持批量评估模式，策略通过 `StrategyBase` 基类实现完整的求解流程。系统已具备结果记录能力（issue #13），可复用其轨迹记录机制。本设计在现有架构上添加交互式调试层，不修改批量评估流程。

参见 proposal.md - Why 了解动机。

## Goals / Non-Goals

**Goals:**
- 提供 CLI 交互式调试命令，支持单题运行
- 在策略执行关键点插入断点和单步控制
- 允许实时修改 prompt 和参数
- 可视化执行轨迹并支持导出

**Non-Goals:**
- 图形化调试界面（保留为未来扩展）
- 时间回溯或撤销执行
- 任意位置断点（仅支持预定义关键步骤）
- 修改批量评估模式的现有行为

## Decisions

### 1. 调试模式实现方式：装饰器模式 vs 继承

**决策：** 使用装饰器模式包装现有策略

**理由：**
- 现有策略无需修改即可支持调试
- 调试逻辑与策略逻辑解耦
- 批量模式和调试模式可以复用相同策略实现

**备选方案：**
- 为每个策略创建 Debug 子类 → 需要为所有策略重复实现调试逻辑
- 直接修改 StrategyBase → 污染批量模式，增加复杂度

### 2. 断点实现：Hook 点 vs 事件系统

**决策：** 在策略基类关键方法中插入 hook 点

**理由：**
- 简单直接，易于理解和维护
- 策略关键步骤位置固定（生成、执行、反馈）
- 性能开销最小

**备选方案：**
- 事件驱动系统 → 过度设计，增加复杂度
- AST 修改或 monkey patching → 脆弱且难以调试

### 3. 命令解析：自定义解析器 vs cmd 模块

**决策：** 使用 Python 标准库 `cmd` 模块

**理由：**
- 提供开箱即用的命令循环和补全
- 标准化的命令定义方式
- 支持历史记录和帮助系统

**备选方案：**
- Click interactive mode → 过于复杂，学习曲线陡
- 手写解析 → 重复造轮，缺少补全等功能

### 4. Prompt 编辑：内联输入 vs 外部编辑器

**决策：** 优先使用外部编辑器（$EDITOR），降级到内联多行输入

**理由：**
- 外部编辑器提供更好的编辑体验（语法高亮、撤销等）
- 内联输入作为后备保证可用性
- 遵循 Unix 哲学（利用现有工具）

### 5. 轨迹存储格式：JSON vs 结构化日志

**决策：** 使用 JSON 格式

**理由：**
- 结构化，易于程序化分析
- 与现有结果记录格式一致
- 支持完整的数据类型和嵌套结构

## Risks / Trade-offs

**[风险] Hook 点可能影响性能**
→ **缓解：** Hook 仅在调试模式下启用；批量模式零开销

**[风险] 用户修改 prompt 可能导致策略失效**
→ **缓解：** 记录所有用户干预到轨迹中，便于追溯；在执行前显示修改后的完整 prompt

**[风险] 外部编辑器可能不可用或配置错误**
→ **缓解：** 降级到内联多行输入模式，确保基本可用性

**[权衡] CLI 交互限制了并发调试**
→ **接受：** 调试模式本身就是串行的；未来可扩展为 Web UI 支持多会话

**[权衡] 固定断点位置限制了灵活性**
→ **接受：** 三个关键点（生成、执行、反馈）覆盖大部分调试需求；任意位置断点需要更复杂的实现

## Architecture

### 模块结构

```
harness/
├── cli/
│   └── debug.py           # 调试命令入口
├── debug/
│   ├── __init__.py
│   ├── debugger.py        # 调试器主循环（cmd.Cmd 子类）
│   ├── strategy_wrapper.py  # 策略装饰器
│   ├── breakpoint.py      # 断点管理
│   ├── trace.py           # 轨迹记录和可视化
│   └── editor.py          # Prompt 编辑功能
└── strategies/
    └── base.py            # 扩展 hook 点
```

### 核心交互流程

```
用户执行 harness debug --problem X --strategy Y
  ↓
创建调试器实例和策略装饰器
  ↓
进入 cmd 交互循环
  ↓
用户命令：next / continue / edit-prompt / set / inject / trace / export
  ↓
策略执行到 hook 点时暂停
  ↓
显示当前状态，等待用户命令
  ↓
重复直到完成或用户退出
  ↓
询问是否保存轨迹
```

### Hook 点设计

在 StrategyBase 中添加三个 hook 点：
- `_before_generate(prompt)` → 生成代码前
- `_before_execute(code)` → 执行代码前
- `_after_feedback(feedback)` → 收到反馈后

调试装饰器在这些点检查断点状态，决定是否暂停。

## Migration Plan

本功能为新增能力，无需迁移现有数据或代码。

**部署步骤：**
1. 实现核心调试模块（不影响现有功能）
2. 在 StrategyBase 中添加 hook 点（默认为空操作）
3. 添加 CLI 命令入口
4. 更新文档和使用指南
5. 运行回归测试确保批量模式不受影响

**回滚策略：**
- Hook 点为可选调用，移除不影响现有功能
- 调试命令独立，可直接删除 debug 模块
