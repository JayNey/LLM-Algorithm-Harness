## Context

现有 API 全部使用 `/api/v1`，应用发布版本为 0.1.0。OpenAPI 在无需启动服务和外部依赖时生成，现有 CI 执行全部 pytest 测试。

## Decisions

- 沿用 URL 主版本：调用方、代理、curl 均可直接识别版本。Header 版本增加隐式协商和缓存复杂度，本项目不采用。
- OpenAPI info.version 标记 HTTP 契约版本 1.0.0；健康检查的 version 继续表示应用发布版本 0.1.0。概览与每个操作标注 v1，说明 WebSocket 沿用路径主版本。
- 将变更前的 HTTP 操作及全部引用组件冻结为 JSON 基线。比较剔除文档注释后的既有操作、组件和全局契约配置；允许新增路径、方法和组件。既有结构变化一律要求审查，含可能兼容的变化，采用保守门禁而非不完整的语义兼容推断。
- 不从当前生成结果自动覆盖基线；基线更新必须先检查旧版仍可使用，并在 PR 解释变更原因。业务语义与 WebSocket 帧由现有运行时回归覆盖，OpenAPI 检查不证明这些行为兼容。

## Risks / Trade-offs

- FastAPI/Pydantic 升级可能导致结构重排或命名变化 → 检查差异并人工审查，禁止仅为通过测试重录基线。
- 保守检查可能拦截兼容的 schema 扩展 → 经过审查后更新基线；新增端点无需更新已有基线。
- 基线只覆盖已发布的 HTTP 契约 → 保留现有单元及集成测试。
