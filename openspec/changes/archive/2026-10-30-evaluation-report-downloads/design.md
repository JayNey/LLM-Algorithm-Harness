## 背景

动机见 `proposal.md`，用户可见约定见 `specs/frontend/result-reports/spec.md`。`ResultDetailPage` 已有认证后的评估客户端、当前结果 `run_id` 和 `ResultAvailability`。后端报告路由返回文件响应，并按运行归属校验访问权限。

## 目标与非目标

**目标：**

- 复用已配置的 API 地址和认证 HTTP 客户端，保持 Cookie/CSRF 处理与会话刷新行为一致。
- 下载请求始终绑定到当前结果的 `run_id`。
- 在报告操作附近显示进度和错误，并在下载后释放浏览器对象 URL。
- 使用页面现有的结果可用性事实解释报告是否完整。

**非目标：**

- 不新增或修改后端报告路由、报告内容或归属规则。
- 不接入 P7 跟踪的独立结果导出/文件产物路由。

## 关键决策

- 在评估模块新增相邻报告客户端提供报告请求，只接受 `markdown`、`html` 或 `csv`，要求非空 `run_id`，并返回响应 Blob 与安全文件名。这样仍经同一个 Axios 实例和配置的 API 地址发出请求；单独使用 `fetch` 或浏览器直接导航会绕过现有会话刷新。
- 响应头 `Content-Disposition` 中的文件名有效时优先使用，否则按运行 ID 和格式生成默认名。当前 API 使用 RFC 5987 `filename*`；需防御性解析和解码，不能假设该头一定存在。
- 结果详情只在有 `run_id` 时显示三个格式操作；记录进行中的格式以阻止重复请求，把错误显示在页面内，通过临时对象 URL 触发下载后移除临时链接并撤销 URL。
- 复用 `ResultAvailability`：除已确认完整外的状态都显示部分报告提示。不能根据 HTTP 成功或报告文件存在就推断评估完整。

## 风险与取舍

- **[风险]** 以 Blob 读取的错误响应可能不含可直接读取的 JSON 详情。**缓解：**保留 HTTP 客户端的状态码和通用错误，显示可重试提示，且不把错误响应当文件处理。
- **[风险]** 畸形文件名响应头可能产生不安全文件名。**缓解：**只解析受支持的文件名参数，拒绝路径分隔符和控制字符，并回退到生成的安全名称。
- **[风险]** 未完成运行的报告在应用外打开时看起来像最终报告。**缓解：**把部分/不完整提示放在下载操作旁边，并使用现有的可用性状态。

## 迁移计划

无需迁移。部署后前端开始调用现有接口；回滚时撤销前端改动即可。
