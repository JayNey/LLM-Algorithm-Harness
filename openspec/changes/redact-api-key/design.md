## Context

API Key 目前是普通字符串。完整配置会被记录，第三方异常文本也会被原样传递，单独删除一个日志字段不能保护后续配置导出或报告。

## Goals / Non-Goals

**Goals:**

- 原始密钥只在模型 SDK 初始化边界出现。
- 为配置、日志、异常和导出提供一致的递归脱敏规则。
- 保持直接配置密钥和现有默认环境变量用法兼容，并支持显式环境变量引用。

**Non-Goals:**

- 不建设远程密钥服务或系统钥匙串集成。
- 不修改模型请求参数、重试策略或供应商响应协议。

## Decisions

1. **使用 Pydantic `SecretStr` 保存 API Key。** 模型的表示和 JSON 序列化默认不暴露原文，客户端通过 `get_secret_value()` 在最后一刻取值。
2. **增加单一递归脱敏工具。** 敏感字段名、Bearer 凭证、常见键值文本和调用方明确提供的已知秘密都替换为 `[REDACTED]`。
3. **在日志处理器和导出边界重复应用同一工具。** 这使嵌套对象和未来新增字段默认受保护，并对历史普通字典保持兼容。
4. **模型客户端负责解析秘密来源并清理异常。** 空值继续回退到供应商默认环境变量；`env:NAME` 和 `${NAME}` 解析指定变量；缺失时只报告变量名，不输出其他环境内容。初始化时实际交给 SDK 的值以 `SecretStr` 保存，确保环境变量随后变化时仍能清理供应商回显的旧密钥，同时避免对象表示暴露原文。

## Risks / Trade-offs

- [文本模式可能误删看似凭证的普通内容] → 规则限定在敏感键值、Bearer 头和已知秘密，不做任意字符串全局遮盖。
- [秘密类型不再等同于普通字符串] → 仅模型客户端读取原始值，其他代码使用安全序列化视图。
