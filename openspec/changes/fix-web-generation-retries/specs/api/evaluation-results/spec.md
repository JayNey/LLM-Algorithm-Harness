## MODIFIED Requirements

### Requirement: 失败分析不重建隐藏证据

失败汇总、按标签的弱项和失败案例 SHALL 使用结果行上已保存的状态、`failure_mode`、`failure_category`、`error_message` 和已保存的迭代错误，以及题库中的难度与标签。结果明细、错误聚类和失败案例 SHALL 显示已脱敏的错误类型和发生阶段，区分生成超时、限流、鉴权和沙箱错误。普通错误信息聚类 SHALL 使用现有错误分析的归一化规则。系统 SHALL NOT 读取隐藏测试输入或未落库的沙箱轨迹来补充分类。

#### Scenario: 按已保存的失败模式汇总

- **WHEN** 一次运行的失败单元已经保存了 `failure_mode`
- **THEN** 失败汇总按这些模式计数，且不因缺少沙箱轨迹而改写模式

#### Scenario: 失败案例只包含失败单元

- **WHEN** 用户请求某次运行的失败案例
- **THEN** 列表只包含非成功单元，并带有已保存的错误信息；成功单元不出现

#### Scenario: 历史迭代超时可见

- **WHEN** 历史失败单元的顶层错误为空且已保存的迭代记录包含生成超时
- **THEN** 单题明细、失败案例和聚类显示模型生成超时，且不返回供应商原始响应
