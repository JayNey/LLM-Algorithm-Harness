## Context

现有 `src/reporting/chart_generator.py` 已实现三种图表：成功率柱状图、Token 折线图、迭代分布直方图。`src/reporting/html_generator.py` 直接调用图表生成器并将 Base64 图片嵌入 HTML。用户反馈需要增强 Token 图表的数据展示（误差线、成本估算）、改进迭代分布的可读性（分组柱状图）、提升 HTML 报告鲁棒性（图表渲染失败处理）。

约束：
- 保持现有 API 签名向后兼容
- 不修改 `models.py` 中的数据模型
- matplotlib 已在项目依赖中

## Goals / Non-Goals

**Goals:**
- Token 图表显示 25%/75% 分位数误差带和双 Y 轴成本估算
- 迭代分布图改为按策略分组的柱状图，支持多策略对比
- HTML 报告在单个图表失败时仍能生成完整报告

**Non-Goals:**
- 修改图表样式系统（颜色、字体、尺寸保持现有规范）
- 新增其他类型图表
- 修改 CSV/Markdown 生成器

## Decisions

### 1. Token 图表误差线实现方式

**选择：使用 `ax.fill_between()` 绘制 25%/75% 分位数区间**

理由：
- matplotlib 的 `fill_between()` 原生支持误差带渲染
- 比 `errorbar()` 更适合展示分位数范围（非标准差）
- 透明度填充不影响主折线可读性

替代方案：
- `ax.errorbar()`：更适合标准差，不适合分位数
- 分别绘制上下界线：视觉混乱，难以识别范围

实现：
- 计算每个策略在每个问题的 Token 消耗分位数
- 使用 `alpha=0.2` 的半透明填充
- 颜色与主折线匹配

### 2. 成本估算的双 Y 轴设计

**选择：左轴显示 Token 数量，右轴显示美元成本**

理由：
- 双 Y 轴同时展示数量和成本，无需切换视图
- 成本单价可配置（默认 $0.01/1K tokens），适应不同模型
- 右轴刻度自动与左轴 Token 数同步

替代方案：
- 单独生成成本图表：增加图表数量，对比不便
- Tooltip 显示成本：交互性差，静态报告无法使用

实现：
- 新增 `token_cost_per_1k` 参数（默认 0.01）
- 使用 `ax.twinx()` 创建右轴
- 右轴刻度 = 左轴刻度 * (token_cost_per_1k / 1000)

### 3. 迭代分布图改为分组柱状图

**选择：使用 `plt.bar()` 的分组模式，每个策略一组柱子**

理由：
- 分组柱状图直接对比不同策略在相同迭代次数的频率
- 比直方图更适合离散的迭代次数（1, 2, 3...）
- 支持多策略并列，清晰展示分布差异

替代方案：
- 保持直方图：bin 划分不适合小整数，策略对比困难
- 堆叠柱状图：总和不重要，并列更直观

实现：
- X 轴为迭代次数（1, 2, 3...）
- 每个策略一个颜色，柱子并列放置
- 使用 `width / num_strategies` 控制柱宽

### 4. HTML 图表渲染异常处理

**选择：在 `html_generator.py` 的图表生成调用处增加 try-except**

理由：
- 局部失败不应影响整个报告生成
- 占位符（错误消息 + 数据摘要）比空白更友好
- 保持现有 `chart_generator.py` 纯净（不包含 HTML 逻辑）

替代方案：
- 在 `chart_generator.py` 内部处理：违反单一职责，图表生成器不应知道 HTML 上下文
- 静默跳过失败图表：用户不知道发生了什么

实现：
- 每个图表生成包装在 try-except 中
- 失败时生成占位符 `<div>` 显示错误类型和策略名称
- 记录完整异常到日志（如果有日志系统）

## Risks / Trade-offs

### 风险 1：分位数计算在样本量小时不稳定
- **影响**：少于 4 个测试用例时，25%/75% 分位数可能失真
- **缓解**：文档说明建议至少 10 个测试用例；少于 5 个时在图表标注警告

### 风险 2：双 Y 轴可能误导读者
- **影响**：不同刻度范围可能夸大/弱化成本差异
- **缓解**：右轴标签明确标注单价（如 "Cost (USD, $0.01/1K)"）；图例说明计算方式

### 风险 3：分组柱状图在策略数 > 5 时拥挤
- **影响**：柱子过窄，难以点击或阅读
- **缓解**：动态调整图表宽度（`figsize[0] = max(10, num_strategies * 2)`）；超过 5 个策略时建议分组展示

### 权衡：向后兼容 vs. 新参数
- **决定**：新增可选参数而非修改现有参数
- **影响**：API 签名变长，但现有调用无需修改
- **示例**：`generate_token_chart(data, show_percentiles=True, token_cost_per_1k=0.01)`
