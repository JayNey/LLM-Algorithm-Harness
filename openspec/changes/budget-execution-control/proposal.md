## Why

Web 保存的个人预算目前只参与成本展示；评估 worker 的暂停判断只读取单任务上限，未读取个人预算及 pause/downgrade 动作。因此用户设置个人预算后，实际任务仍可能继续按原策略执行。

## What Changes

- 将个人预算接入实际任务执行的单元调度检查，按任务所有者读取配置与累计用量，隔离其他用户。
- 个人全局预算触顶时执行 pause 或 downgrade；按难度预算仅影响对应难度，明确用量口径，避免将展示用估计值冒充精确执行账本。
- 保留既有单任务预算暂停约束；个人预算降级不能绕过单任务上限或手动暂停。
- 为暂停后的恢复重新检查预算，保留已完成结果和成本，避免恢复时重复计费或重复执行。
- 验证实际 worker 路径中的暂停、降级、恢复、用户隔离与未配置预算兼容行为。

## Capabilities

### New Capabilities

无；扩展现有成本管理及任务执行能力。

### Modified Capabilities

- `api/cost-management`：个人预算从持久化配置和用量展示扩展为实际执行控制。

## Impact

已定位入口为 `src/tasks/evaluation.py` 的串行单元调度、成本落库回调与暂停判断；预算数据和用量聚合位于 `api/services/cost_service.py`，现有 `Budget` 表保存全局上限、难度分配与动作。优先复用现有模型和暂停机制，不预设数据库迁移或新增 HTTP API。

实现口径、降级策略及执行元数据已在 design.md 明确。用户选择 A2，在知悉跨模块协调后继续单一 Tweak change，并创建独立分支。
