## 实现
提取现有 Slack/Webhook/SMTP 传输为无状态发送器，CLI 保留原状态机制。Web dispatcher 使用 worker 独立数据库会话，检查 enabled 规则及 owner 全局预算；用与执行预算相同的全局用量口径（评估及已完成 benchmark）判断百分比，覆盖 100%。只读取当前用户规则。

成功发送后记录 AlertEvent；相同规则、阈值和预算上限仅成功投递一次，恢复后仍去重。目标或预算需重新通知时可建立新规则；预算上限变化自动重新计数。失败每次 worker 实例仅进行一组有界重试，恢复可重试；不记录成功历史。PostgreSQL 对用户预算行加锁协调并发 worker；SQLite 使用写事务串行化。网络发送与本地提交之间存在崩溃重复窗口，不承诺 exactly-once。

SMTP 使用 COST_ALERT_SMTP_* 环境变量，target 仅为收件地址。所有渠道超时和重试复用发送器默认值。仅 HTTPS URL，无内嵌账号；异常不输出 URL、密码或收件地址。每次边界重新读取规则，禁用立即生效；通知不改变预算暂停/降级。

## 验证
HTTP 保存规则到真实 TaskService 执行的集成测试；通道 payload、100% 边界、失败隔离、恢复去重、用户隔离与规则禁用。相关回归及代码检查。
