# 提议：Reflexion 反思式学习策略

## Problem

现有多轮反馈策略会把测试结果直接交给模型继续修改，缺少独立的失败归因步骤。模型容易重复同一种逻辑错误，也无法在结果中审计它为什么改变代码。

## Goal

- 新增可通过 `reflexion` 名称选择的策略。
- 在每次可见测试失败后先生成一条结构化反思，再生成下一版代码。
- 将反思文本、调用耗时、Token、定价和错误写入迭代记录，并纳入总 Token 与成本统计。
- 严格限制反思上下文长度，只使用公共测试和反馈测试，不泄露隐藏测试。
- 覆盖成功收敛、上下文截断、公开测试阶段和预算停止行为。

## Non-goals

- 不改变隐藏测试评估协议。
- 不引入新的模型供应商或持久化数据库。
- 不把反思当作可执行代码，也不允许反思调用绕过现有预算客户端。
