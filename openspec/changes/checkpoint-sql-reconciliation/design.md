## 实现方案
保留文件先提交的顺序，把文件终态结果作为可重放输入。恢复前验证配置与数据指纹，再在现有业务任务锁及代际检查下对账 completed/failed 且非 uncertain 的单元。SQL 结果以 evaluation/problem/strategy 为稳定键，费用使用新旧结果成本差额，与结果、计数和发布快照同事务提交；重复重放差额为零。
检查点 completed 而 SQL 任务仍 running 时也恢复，不创建新任务。对账在预算检查之前完成，防止少计费用继续派发。最终状态提交后重新发布快照，覆盖最后一次 SQL 提交后进程退出的窗口。

## 验证
确定性注入文件保存前后、结果 SQL 提交前后退出，覆盖最后单元、失败单元及重复恢复；已确认单元不再执行。使用真实 Redis 与 prefork Celery worker 在文件完成后 SQL 提交前退出，检查 redelivery、结果与费用；模型使用固定本地替身。
