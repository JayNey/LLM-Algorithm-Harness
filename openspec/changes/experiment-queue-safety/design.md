## Context

实验服务只检查业务 pending，没有在事务中检查关联任务。通用 enqueue_task 已实现先提交再发布、发布异常时条件更新任务并同步实验，#295 已保护取消终态。

## Goals / Non-Goals

修复一次实验提交的并发互斥及前端任务恢复；不添加重试/恢复协议，不修改通用队列与 Worker 的终态规则。

## Decisions

- 参照 A/B 服务，在任何读取之前 UPDATE 所属实验获取数据库写锁，随后检查业务状态和已有任务，直到 enqueue_task 提交记录才释放。SQLite 与 PostgreSQL 均由数据库协调，不依赖进程锁。
- 删除同样先获取实验写锁；running/paused 业务或任一 pending/running/paused 关联任务均拒绝删除。保留终态任务，确保 P1 的迟到消息仍能看到 cancelled。
- task_id 由所有者、类型、实体匹配查询，详情/列表返回最新任务标识；列表批量查询，未提交返回 null。
- 前端解析关联并优先使用它，旧响应缺字段时完整分页查询 pending/running/paused 作为兼容回退。关联恢复未完成或失败时不允许启动。排队、运行、暂停支持取消并禁止删除；终态允许删除。
- 回归覆盖同库独立进程同时提交、提交/删除竞争、发布失败、所有者隔离和原有取消同步。

## Risks / Trade-offs

发布超时不能证明消息未送达，沿用通用队列的条件失败更新保护已启动/取消状态；不引入自动重试。旧数据库已有重复任务不做自动清理，删除检查所有活动任务。无需迁移。
