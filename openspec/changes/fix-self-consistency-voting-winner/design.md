## 修复方案

让 `_vote_on_candidates()` 在返回沙箱结果的同时返回 `selected_code`。成功分支取胜者代码，全失败分支取最后一个候选代码（空列表或无代码时为空字符串）。`execute()` 在通用结果构造完成后将 `generated_code` 赋为该选择值。

该方案不修改通用结果构造接口，也不重排或截断 iterations，因此保留候选记录、计费信息与报告元数据。平票仍按首次出现的候选选择；修正文档中“全失败返回首个候选”的过时描述，使其与现有最后候选回退一致。

## 验证

先通过现有 mock LLM / sandbox 边界复现执行结果错误，再运行回归测试确认修复。覆盖末尾为落选通过候选、失败候选、无代码响应及模型错误，平票、唯一通过、全失败、单候选和空候选；检查胜者代码与最终测试结果一致、原始迭代与 token/traces 完整。执行策略相关测试、格式/静态检查和 Python 包构建。
