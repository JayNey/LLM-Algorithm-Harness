## 背景

用户可见改动见 `proposal.md` 和两个 delta spec。当前 worker 实现及 `docs/cost-alerts.md` 是 Web 预警触发条件和 SMTP 配置的事实来源。导入状态接口可以报告暂停任务；最新 main 已支持导入等业务任务恢复，但前端仍没有通用任务管理页或题库导入恢复/取消控件。

## 目标与非目标

**目标：**

- 让预算提示准确描述已实现的渠道、触发条件和部署配置。
- 为暂停导入提供可执行的说明，不承诺不存在的页面操作。
- 将改动限制在提示文案、可见的导入任务标识和对应翻译。

**非目标：**

- 不实现新的通知投递、站内通知、任务管理或导入恢复/取消控件。
- 不改变 worker 的预警时机、导入任务生命周期或后端 API。

## 关键决策

- 将 Slack/Webhook 目标描述为规则配置，将 SMTP 设置描述为 worker 环境配置。说明投递由 Web 评估的成本检查边界尽力触发，需要启用规则和个人全局预算，且没有后台轮询。这与当前实现和 `docs/cost-alerts.md` 一致；继续显示“投递未实现”会误导用户。
- 保留预算页提示，但明确保存规则不代表消息已投递，并说明站内通知中心仍为 Mock。
- 暂停导入时，不再指向不存在的任务列表；说明此页面不能恢复或取消，原任务未查明前避免再次提交，持续暂停时联系管理员。显示现有 `job_id` 便于排查，保留当前进度轮询。
- 在 zh-CN 与 en-US 中使用对应翻译，不链接到不存在的路由。

## 风险与取舍

- **[风险]** 如果 worker 触发条件或部署要求改变，提示文案可能过期。**缓解：**让提示与当前实现和文档一致，不承诺一定成功投递。
- **[风险]** 用户不能从此页面恢复暂停的导入，可能需要管理员协助。**缓解：**直接说明限制、显示任务 ID，并提醒避免重复提交。

## 迁移计划

不需要迁移。本设计不修改后端或持久化数据。
