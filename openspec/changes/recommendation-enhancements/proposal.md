# Proposal: 推荐系统增强——难度梯度、成本估算与提升维度（issue #91）

## Why

推荐系统主体（PR #67：弱项分组识别、按标签推荐未评估题目、推荐理由、导出新数据集）已交付。issue #91 的验收项中仍有三点缺口：推荐列表未体现难度梯度（从易到难）、缺少练习成本估算、未呈现预期提升的能力维度。

## What Changes

- **难度梯度**：推荐列表在保持相关度（最高失败率优先）入选逻辑不变的前提下，最终输出按难度从易到难排序（easy → medium → hard），便于循序渐进练习。
- **练习成本估算**：基于历史记录的 llm_traces 结算每题所属难度的已知定价平均成本（口径与预算/成本模块一致：usage/pricing 未知不计入）；推荐题均为未评估题、无自身历史，估算取同难度均值，无数据标注"未知"；报告给出推荐集总估算成本。
- **预期提升维度**：每条推荐输出其匹配的弱项标签（结构化 `expected_improvement_dimensions`），报告汇总本次推荐覆盖的能力维度集合。
- 以上均为增量字段/排序调整，既有推荐理由、入选集合与既有字段、弱项报告保持不变（导出数据集会随推荐条目携带新字段）。

## Capabilities

### New Capabilities

- `problem-recommendation`: 推荐列表难度梯度、练习成本估算与预期提升维度的验收要求。

### Modified Capabilities

（无——既有推荐行为要求此前未成 spec，本次一并成文且不改变相关度入选逻辑）

## Impact

- 代码：`src/recommender.py`（梯度排序、成本估算、维度提取）；`tests/test_recommender.py` 增补；README 更新。
- 兼容性：新增字段与排序调整；`recommendation_score` 与入选集合不变。
