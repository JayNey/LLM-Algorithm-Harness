## Context

表单拒绝非正值，定价客户端也在提交响应、目录和历史的解析中拒绝零价。API 使用排他下限。定价覆盖版本和费用记录已分别用数值和空值表示已知价格与未知费用。

## Goals

统一输入和输出的非负价格边界，保留表单必填语义，验证零价走完整的保存与计费路径。

## Decisions

- 表单先拒绝空白，再检查转换结果是否有限且大于等于零。提交、目录和历史使用同一个价格解析规则。
- API 使用含零下限。OpenAPI 兼容性基线只更新这两个字段的下限，现有正值请求继续有效。
- 使用真实持久化和计费回归验证零价与缺失价格的区别，沿用已有价格快照和费用汇总。
- 用户确认继续 Tweak。文件数量来自同一定价契约涉及的代码、翻译、测试和 OpenAPI 基线。
