## Context
现有 API 使用 FastAPI，认证与业务数据分别持久化；现有测试没有独立性能目录。

## Goals / Non-Goals
覆盖 issue 五项验收。基准衡量 API 控制面读取及业务查询，不推断 LLM 执行时间或生产容量。

## Decisions
- Locust 通过环境配置在恒定负载、递增压力、突发并发三种形状间切换，使用真实认证和分页查询。
- 本地 fixture 采用临时文件 SQLite、真实迁移、真实认证及预置评估/任务/题目，生命周期结束后删除。
- HTTP 基准使用 TestClient、线程并发与预热；数据库调用真实 ProblemStore 以及评估列表查询。计时覆盖查询到结果物化，初始化和预热不进入样本。
- JSON 输出包含运行环境、行数、并发、样本、错误、p50/p95/p99 和吞吐量；可选 p95 门限使命令返回非零。
- 长时间性能测试手动运行；普通 pytest 仅检验工具及小规模真实并发，不增加机器相关的默认延迟门限。

## Risks / Trade-offs
本地 SQLite 和进程内 HTTP 无法代表生产网络与 PostgreSQL；报告明确标注模式。Locust 429 和认证失败计入失败，不伪装为成功；长时间运行需要有效 token。
