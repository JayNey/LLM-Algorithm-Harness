## Context

评估 worker 在单元结束后只把 `current`、`total` 和 `message` 写入 Celery 进度。任务查询在运行中会把这份 Celery 进度同步回任务记录。实验、导入和基准已经把 `percentage` 和 `current_step` 写入任务记录上的同一份 JSON。见 proposal.md 的 Why。

## Goals / Non-Goals

**Goals:**

- 在每个评估单元开始前更新任务进度，使查询能看到百分比和当前步骤。
- 百分比与已完成单元数、单元总数使用同一分母，并限制在 0 到 100。
- 当前步骤只保留策略和题目标识。

**Non-Goals:**

- 不改评估详情进度接口的题目数分母，也不把当前步骤加到该响应模型。
- 不新增表、列或接口，不改暂停、恢复和取消行为。
- 不改实验、导入和基准的进度口径。

## Decisions

1. 进度继续写入任务记录已有的 JSON，字段为 `current`、`total`、`percentage`、`current_step`。百分比用现有的完成比例计算：总数为 0 时为 0，其余限制在 0 到 100。
2. 在单元提交执行前写入。`current` 为当时已结束的单元数，`current_step` 为 `策略/题目标识`。百分比表示已完成比例，当前步骤表示即将执行的单元。
3. 同一份进度同时写入任务记录和 Celery 进度。任务查询同步 Celery 状态时不会把新字段覆盖掉。暂停、完成和失败都不清除已写入的进度。
4. 只在任务仍为 `running` 时写入。执行循环增加一个可选的单元开始回调，回调留在持有数据库会话的线程上。
5. 相对 `main` 有 16 个路径，超过文件数提示。用户选择继续 tweak 并进入验证：多出来的是 change 元数据，代码只有任务执行循环、评估 worker 和对应测试。

## Risks / Trade-offs

- [当前步骤含策略名和题目标识] → 这些标识本来就出现在评估配置和结果记录中；不写入题目正文、输出或密钥。
- [单元开始前的百分比尚未包含该单元] → 与实验、基准一致：百分比是已完成比例，当前步骤是即将执行的单元。
- [评估固定单线程执行] → 同一时刻只有一个即将执行的单元，进度不会被并行单元互相覆盖。

## Migration Plan

只改变运行中评估任务的进度 JSON。旧任务没有这些字段时保持原样。回滚时停止写入新字段，已写入的 JSON 可继续被查询。
