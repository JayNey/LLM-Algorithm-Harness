## Context
用户选择新分支并继续 tweak。API/worker 已通过 task_data 共享检查点目录。
## Decisions
在 data/tasks/<evaluation_id> 的稳定锁文件上持有非阻塞 OS 排他锁，覆盖完整 worker（含异常处理、产物与费用回调）。锁文件不得删除或替换。锁不按时间失效，仅在全部在途执行结束或进程死亡后释放；接管前旧执行者不能继续写入，从而提供 fencing。重复消息通过 Celery retry 重投递，不写业务失败。无锁原语时拒绝执行。
暂停恢复两入口探测同一锁，旧执行者尚活跃则拒绝恢复。取消使用 TaskService 可选等待模式，避免后台线程越过执行权释放边界。
## Risks / Trade-offs
所有 API/worker 必须共享支持 OS 文件锁的任务目录。存活但挂起的 worker 须先由运维终止后才能接管。不支持孤立检查点目录的分布式部署。供应商已执行但结果尚未落盘的崩溃窗口仍有 uncertain 重试风险，保持 #337 语义，不声称外部调用恰好一次。
## Validation
独立进程竞争及死亡释放、重复消息不得进入 harness、暂停恢复双入口、取消在途收尾、旧代拒绝和 #337 提交窗口/费用对账。
