# Proposal: 成本预警、通知与超预算暂停（Issue #86）

## Why

现有 `--budget-cap` 只在难度策略选择器中启用：已知成本达到上限后，后续题目改用最便宜策略。用户无法在接近预算时收到通知，也无法选择在超预算时停止派发新题。运行中断后还需要可靠地识别已通知的阈值，避免恢复时重复发送。

## What Changes

- 为有运行级预算的 CLI 评测增加成本阈值预警。默认阈值为预算的 50%、80%、90%，支持自定义；每个阈值在同一任务内只触发一次成功通知。
- 支持 Slack Incoming Webhook、通用 HTTPS JSON Webhook 和 SMTP 邮件。通知包含任务身份、阈值、已知累计成本、预算与未知成本计数；成功渠道及失败渠道的尝试次数和错误类别记录在独立的预警状态文件中。凭据和含密钥的 URL 不进入日志、任务记录或报告。
- 增加显式 `--auto-stop-on-budget`：以单个工作线程运行，已知累计成本达到预算时停止派发新题，任务进入 `paused`，并产出 `cost_cutoff.json` 与 `summary.json.cost_control`。
- 保留现有策略选择器的默认预算降级行为；`--downgrade-on-budget` 可显式选择降级模式。两个动作互斥。未启用预算控制时既有评测与固定预算实验不变。

## Capabilities

### New Capabilities

- `cost-alerts`：阈值触发、多渠道通知、失败记录、超预算暂停与截断报告。

### Modified Capabilities

- `cost-aware-strategy-selection`：明确原有预算降级是选择器模式的默认动作，显式自动暂停模式覆盖该动作。

## Impact

- 代码：成本台账与通知分发、`HarnessConfig` 配置校验、`TaskService` 暂停状态与持久化、CLI 参数、报告输出。
- 产物：任务记录新增暂停事件；独立预警状态文件保存渠道发送状态；运行目录新增截断报告，并在摘要中增加成本控制信息。
- 兼容性：预算降级默认行为保留；配置和数据集指纹仍用于恢复校验。通知为外部副作用，恢复只保证已持久化的成功发送不会重复，进程在发送成功与落盘之间崩溃时可能重发。
