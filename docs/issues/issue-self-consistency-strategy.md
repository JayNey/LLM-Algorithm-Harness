# [功能] 新增 Self-Consistency 求解策略

## 背景与目标

当前只有 Vanilla、CoT、Multi-Round Feedback 三种策略，缺少基于多样本投票的策略。Self-Consistency 通过并行生成多个候选解并投票选择最佳答案，已在学术界验证可提升 5-15% 准确率，且实现相对简单。

- 分类：求解策略
- 建议优先级：P1（高价值，实现成本中等）
- 相关文档：[feature-roadmap.md](../feature-roadmap.md#1-新增求解策略)

## 工作范围

- 实现 Self-Consistency 策略类，继承 `StrategyBase`
- 并行生成 N 个候选解（N 可配置，默认 5）
- 执行所有候选解的测试，统计通过测试的结果
- 选择出现频率最高的正确答案作为最终输出
- 记录每个候选解的生成过程和投票结果
- 支持温度参数配置以增加候选解的多样性
- 集成到现有评测流程和报告系统

## 验收标准

- [ ] `src/strategies/self_consistency.py` 实现完整且通过单元测试
- [ ] 可通过配置文件指定策略参数（候选数量、温度等）
- [ ] 在标准题目集上运行成功，报告包含投票统计
- [ ] 相比 Vanilla 策略准确率有提升（至少 3-5%）
- [ ] Token 消耗和成本统计准确（N 倍生成成本）
- [ ] 文档更新：README 添加策略说明，配置示例

## 边界

- 仅实现基础投票机制，不涉及加权投票或自适应候选数量
- 适用于有确定性测试用例的问题，不处理开放式问题
- 并行生成使用现有的 LLM 客户端，不引入新的并发框架

## 依赖与关联

- 前置：#14 [功能] 提取可复用评测任务服务（已完成）
- 关联：#15 [功能] 固定预算实验（Self-Consistency 可作为对比策略）
- 后续可扩展：基于代码相似度的聚类投票

## 技术要点

- 使用 `temperature > 0` 增加生成多样性
- 候选解去重：基于代码 AST 或执行结果
- 投票规则：通过所有测试用例的解才参与投票
- 失败处理：所有候选解都失败时返回投票最多的失败结果

## 预期收益

- 实现工作量：约 3-5 天
- 准确率提升：5-15%（学术验证）
- 成本增加：N 倍 Token 消耗（可通过预算控制）
- 差异化竞争点：丰富策略库，提升项目价值
