# [功能] 代码质量评估维度

## 背景与目标

当前评估仅关注正确性（是否通过测试），忽略代码质量。实际应用中，代码的时间复杂度、空间复杂度、可读性同样重要。代码质量评估维度可提供更全面的评价，超越单纯正确性，更符合实际应用场景。

- 分类：评估指标
- 建议优先级：P1（差异化竞争点，工业应用需求）
- 相关文档：[feature-roadmap.md](../feature-roadmap.md#6-代码质量评估维度)

## 工作范围

### 1. 时间复杂度分析
- 静态分析：识别循环嵌套层数
- 性能测试：不同数据规模下的运行时间（10x, 100x, 1000x）
- 复杂度评分：与最优复杂度对比
- 超时问题标注：执行时间超过阈值

### 2. 空间复杂度分析
- 监控内存使用峰值（通过 `memory_profiler` 或沙箱限制）
- 识别不必要的内存分配（如重复创建大对象）
- 空间效率评分：实际内存 / 理论最优内存

### 3. 代码可读性评分
- 集成静态分析工具：
  - `pylint`：代码质量综合评分
  - `flake8`：风格检查
  - `radon`：圈复杂度（Cyclomatic Complexity）
- 评估维度：
  - 变量命名质量（是否使用有意义的名称）
  - 注释覆盖率（是否有必要的注释）
  - 函数长度和嵌套深度

### 4. 代码风格一致性
- 使用 `black --check` 检查格式
- 统计风格偏差数量
- 生成代码风格报告

## 边界

- 仅评估 Python 代码质量，不支持其他语言
- 复杂度分析基于启发式规则，不保证 100% 准确
- 不修改生成的代码，只评估和报告

## 技术要点

### 性能测试
```python
# 生成不同规模测试数据
test_sizes = [10, 100, 1000]
for size in test_sizes:
    input_data = generate_scaled_input(problem, size)
    time_taken = measure_execution_time(code, input_data)
    # 计算时间增长率，推断复杂度
```

### 内存监控
- 使用 `tracemalloc` 或 `resource` 模块
- 沙箱环境设置 `memory_limit`，记录峰值

### 静态分析集成
```python
# pylint 评分
pylint_score = run_pylint(code_file)
# radon 圈复杂度
complexity = run_radon(code_file)
```
