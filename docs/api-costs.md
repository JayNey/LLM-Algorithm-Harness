# 费用统计与实验/A/B 记录

费用接口保留现有字段和路径。`/api/v1/costs/tasks/{id}`、`/costs/summary`、
`/costs/trends`、`/costs/breakdown`、`/reports/cost/{id}` 和 `/budgets/usage`
均按当前登录账号读取。全局预算执行读取与费用汇总使用相同来源：evaluation
累计费用、已完成 benchmark 费用，以及实验和 A/B 已持久化的调用费用。

## 金额与完整性

- `known_cost_usd`：可验证的已知金额小计，单位美元，展示精度六位小数。
- `cost_complete`：范围内是否没有已识别的未知费用部分。
- `unknown_cost_count`：未知调用或历史缺口标记的数量；不是未执行题目数量。
- `unknown_reasons`：按原因分组的未知数量，可能包含 `missing_usage`、
  `missing_pricing`、`missing_response`、`historical_gap`、`historical_partial`。

聚合接口现有的 `total_cost_usd` / `cost_usd` 仍返回已知小计。实验/A/B 的单任务
`total_cost_usd` 在完全未知时为 `null`，部分已知时返回小计且 `cost_complete=false`。
新建尚未发起调用的任务为已知零。不要仅根据金额为零判断任务免费；须同时查看完整性。
趋势的每个日期和汇总的每个来源也带完整性信息。`task_count` 按来源和业务任务去重，
同一任务的多次调用不增加任务数。

实验/A/B 在真实模型响应返回后、结果文件和任务完成状态写入前保存费用。价格沿用
PricingManager 的文件、内置及 Web 覆盖机制，保存当时快照；以后修改价格不会改写旧费用。
缓存命中只增加一条已知零费用记录，不把缓存响应中的旧调用金额再次计费。
费用记录不包含提示词、模型输出或凭据。

## 状态、时间与恢复

运行中、暂停、取消及失败任务的已保存费用均参与统计。任务暂停后恢复时复用已有检查点；
重复消息受现有 worker claim 保护；同一费用事件回放受数据库唯一事件 ID 保护。
模型请求重试前的失败尝试同样保留未知费用记录，即使后续尝试成功，也不会掩盖前次的不确定消耗。
检查点写入前中断而确实重新发起的模型调用产生新的消耗，仍应记账。

实时记录按响应返回时的 UTC 时间归属。日期过滤沿用现有接口规则：日期包含当天全天，
带时区时间戳转换为 UTC。evaluation 和 benchmark 保持既有日期归属规则。
历史快照回填按业务记录的完成时间（无则开始/创建时间）归属，并保存日期依据。
历史缺口标记按任务开始/创建时间归属；日期范围内无标记并不证明范围外的历史完整。

供应商已消耗但响应永久丢失、或进程在数据库提交前退出时，系统无法重建准确金额。
`cost_complete` 描述已识别记录的完整性，不代表供应商账单级对账保证。
可观测的供应商异常会保存未知记录。费用写入失败会阻止该执行器继续请求模型，
并在数据库可用时将任务标记为费用采集不完整。

## 迁移与回填

应用启动将业务数据库升级到迁移 `0005`，创建 `spend_records` 表并将旧实验/A/B
标记为不完整，不凭总 tokens 推测费用。显式运行以下命令检查、再导入可验证的历史快照：

```sh
python -m api.services.spend_records --dry-run
python -m api.services.spend_records
```

命令使用应用的业务数据库配置。只导入历史实验 `experiment.json` 引用的
`summary.json` 中明确的实际定价小计，事件 ID 固定，重复运行不会重复计入。
存在实时调用记录的旧任务会跳过，以免快照与调用重叠。旧 A/B 只有总 tokens 时保持未知；
文件缺失或无法验证时通过 `skipped` 报告，历史整体缺口始终保留。
回滚至 `0004` 会删除新增费用表和完整性字段，保留原业务字段。

分难度预算展示继续注明 evaluation 的比例估计；实验/A/B 能明确归属难度的调用
按真实已知费用加入。执行预算的难度累计只使用实际结果/调用记录，不使用展示估计。
本次提供 P5 所需的读取口径，实验/A/B 新增暂停、降级和预警动作由 P5 实现。
