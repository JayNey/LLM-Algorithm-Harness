# Issue #89 失败模式分类器验证报告

日期：2026-09-30

## 实现核对

- 在既有 `status` 和 `failure_category` 之外记录 `failure_mode`、规则置信度与非敏感证据代码；保持原有七类 `error_analysis` 兼容。
- 规则覆盖语法、逻辑、超时、边界条件、题意理解、运行时、基础设施及无法判定八种模式。对成功、预算耗尽、不支持、取消等非失败结果不分类。
- 普通运行保存总体及每策略的 JSON/Markdown 汇总和失败模式 PNG 分布图；固定预算实验在组合及总体报告和 HTML 面板中展示同一统计。
- 按题目标签分别计算已评估分母与失败率；弱项排序只展示至少 3 条已评估记录的标签。

## 验证结果

- 人工标注的固定离线案例集：**27/27** 条可分类失败判对，另有 **4/4** 条非失败记录正确跳过；八种模式每类至少 3 条。验收门槛为严格大于 85%。这仅衡量案例集上的规则表现，不能当作真实运行的泛化准确率。
- 分类、报告、任务持久化、实验集成及相邻测试：**111 passed**。
- 排除已确认的旧 LLM 客户端缓存测试与两项缺失质量工具的测试后，其余套件：**654 passed、4 skipped、2 deselected**。
- `openspec validate failure-mode-classifier --strict --no-interactive` 与 `git diff --check`：通过。新增分类与报告模块的 Ruff 检查通过。

## 独立审查与修复

独立只读审查提出三项 P2 问题，均已修复并加回归测试：

1. 输出不符诊断会包含期望/实际输出；分类器现在不把这些值误识别为语法、超时或边界线索。
2. 多轮任务的旧沙箱结果可能盖过最后一次模型调用错误；现在按最终模型错误优先分类。
3. 任务服务未产出结果时的合成错误记录会虚增分母；现在用 `evaluation_completed: false` 标记并从细分类与统计中排除。

## 验证边界

- 没有可靠证据时回退到 `logic_error` 或 `unknown`；单次 wrong answer 不会被强行解释为题意或边界错误。
- 仅使用既有运行结果和题目信息，无额外模型调用；没有用真实在线服务评估分类准确率。
- 全量测试中 `test_llm_client.py` 的缓存干扰已在未修改的 `origin/main` 上复现；两项代码质量测试需要本机未安装的 `pylint`、`flake8`、`radon`。本报告的广泛回归结果明确排除了这些既有环境/隔离问题。
